## Pengantar

Buka `src/server.js` milikmu. Setelah [Pagination, Filter, Search & Sort](/belajar/crud-backend/pagination-filter-search), file itu sudah sekitar 150 baris. Isinya campur aduk: logger (pencatat request), health check, enam route tugas, tiga route mata kuliah, handler 404, error handler, dan `app.listen`. Semuanya masih jalan, tapi mulai muncul empat masalah:

- **Sulit dicari.** Mau mengubah cara mencari tugas? Kamu harus menggulir melewati route mata kuliah dan middleware (fungsi "penjaga" yang jalan sebelum handler) dulu.
- **Sulit diuji.** Test adalah kode yang mengecek kode lain secara otomatis. Masalahnya, begitu `server.js` di-import, `app.listen` langsung jalan. Test jadi ikut menyalakan server di port 3000.
- **Konfigurasi tercecer.** `process.env.PORT` dibaca di satu tempat, `process.env.NODE_ENV` di tempat lain. Kalau isi `.env` salah ketik, server tetap menyala lalu baru gagal di tengah request.
- **Ditolak browser.** Saat aplikasi Expo dibuka versi web-nya, browser menolak respons API karena server belum mengaktifkan CORS. Penjelasannya ada di bagian CORS nanti.

Pelajaran terakhir Track 1 ini tidak menambah fitur baru. Kamu merapikan `belajar-api` menjadi beberapa lapisan, sama seperti API pendamping di Track 3. Setiap endpoint tetap memberi respons yang sama persis. Yang berubah hanya letak kodenya. Kegiatan ini disebut **refactor**.

Mirip merapikan kamar kos: buku dan baju tetap sama, hanya dipindah ke rak dan lemari supaya gampang dicari.

## Peta lapisan: route, controller, service

<Callout type="analogi" title="Seperti kantin kampus">

Di kantin, setiap orang punya tugas sendiri. Papan petunjuk mengarahkanmu ke loket yang benar. Petugas loket mengecek pesananmu masuk akal (menunya ada, jumlahnya wajar). Kasir mencatat pesanan, lalu menyerahkan makanan kepadamu. Juru masak memasak tanpa peduli kamu bayar tunai atau QRIS. Bahannya diambil dari gudang.

- papan petunjuk = **route**
- petugas yang mengecek pesanan = **validasi**
- kasir = **controller** (handler)
- juru masak = **service**
- gudang bahan = **Prisma** dan database

Bedanya dengan kantin sungguhan: di backend yang rapi, juru masak tidak pernah bertemu pembeli. Ia hanya menerima daftar pesanan dari kasir.

</Callout>

Backend yang rapi membagi tugas dengan cara yang sama. Satu lapisan, satu jenis pekerjaan:

| Lapisan | Lokasi di `belajar-api` | Tugasnya | Tidak boleh |
| --- | --- | --- | --- |
| **Route** | `tasks.routes.js` | Mencocokkan method + URL ke rangkaian middleware | Berisi logika bisnis |
| **Validasi** | `validate()` + `tasks.schemas.js` | Memastikan `params`, `query`, `body` sesuai schema | Mengakses database |
| **Controller** (handler) | fungsi `async (req, res)` di `tasks.routes.js` | Mengambil data dari `req`, memanggil service, menulis `res` | Menulis query Prisma |
| **Service** | `tasks.service.js` | Logika bisnis dan akses data lewat Prisma; melempar `HttpError` | Menyentuh `req` atau `res` |
| **Data** | `src/lib/prisma.js` | Satu Prisma Client untuk seluruh aplikasi | Dibuat ulang di file lain |

[Controller](/glosarium#controller) adalah si kasir. Ia membaca data dari request, memanggil fungsi service, lalu mengubah hasilnya menjadi status code dan JSON. Banyak tutorial membuat file `tasks.controller.js` tersendiri. Handler kita hanya dua sampai tiga baris, jadi kita menulisnya langsung di file routes, sama seperti API pendamping.

[Service layer](/glosarium#service-layer) adalah si juru masak. Aturannya satu: service tidak pernah menyentuh `req` atau `res`. Ia menerima argumen biasa (angka, objek), lalu mengembalikan data atau melempar error.

<CompareItem title="Hindari" tone="bad">

```js
}
```

### Folder per fitur, bukan per jenis file

<Callout type="analogi" title="Map per mata kuliah">

Ada dua cara menyimpan kertas kuliah. Cara pertama: satu map untuk semua catatan, satu map untuk semua tugas, satu map untuk semua kuis. Cara kedua: satu map per mata kuliah. Map "Basis Data" berisi catatan, tugas, dan kuis Basis Data. Menjelang UAS Basis Data, cara kedua jauh lebih enak karena semua bahannya ada di satu map.

Cara pertama = folder **per jenis file**. Cara kedua = folder **per fitur**.

</Callout>

Gaya per jenis membuat folder `routes/`, `controllers/`, dan `services/`. Gaya per fitur membuat satu folder untuk setiap fitur, misalnya `modules/tasks/`. Kita memakai gaya per fitur karena:

- Saat mengubah fitur tugas, semua file yang terkait ada berdekatan.
- Menambah fitur baru cukup dengan menambah satu folder di `modules/`.

Kode yang dipakai bersama oleh semua fitur tetap di `lib/` dan `middleware/`. Anggap saja alat tulis yang kamu simpan di tas, bukan di salah satu map.

## Konfigurasi lewat environment variable

<Callout type="analogi" title="Laptop yang sama, Wi-Fi yang berbeda">

Kamu membawa laptop yang sama ke kampus, ke kos, dan ke rumah. Laptopnya tidak berubah. Yang berbeda hanya nama Wi-Fi dan password yang kamu masukkan di tiap tempat.

- laptop = kode `belajar-api`
- nama Wi-Fi dan password = **environment variable** (`PORT`, `DATABASE_URL`, dan lainnya)
- catatan pribadimu "di kos pakai Wi-Fi ini" = file `.env`

Password Wi-Fi juga tidak kamu tempel di pintu kos. Begitu pula nilai rahasia di `.env`: tidak ditulis di kode dan tidak dibagikan.

</Callout>

[Environment variable](/glosarium#env-variable) adalah pengaturan yang diberikan dari luar kode. Contohnya nomor port, alamat database, dan mode (development atau production). Dengan `.env` yang berbeda, kode yang sama bisa berjalan di laptopmu dan di server kampus.

Ada satu jebakan. Isi `process.env` selalu berupa teks (string) atau `undefined`. Jadi salah ketik seperti `PORT=abc` tidak langsung ketahuan. Server tetap menyala, lalu error di tempat yang membingungkan.

Solusinya: periksa semua variabel sekali saja saat server baru menyala, memakai Zod yang sudah kamu kenal. Kalau ada yang salah, server langsung berhenti dengan pesan yang jelas. Prinsip ini disebut **fail fast** (gagal secepatnya), seperti driver ojek yang mengecek bensin di garasi, bukan setelah mogok di jalan.

Instal dulu dua paket yang akan dipakai sebentar lagi (penjelasannya ada di bagian CORS):

```bash
npm install cors helmet
```

Lalu buat `src/config/env.js`:

```js title="src/config/env.js"
import "dotenv/config";
import { z } from "zod";

// Pesan bawaan Zod berbahasa Indonesia untuk seluruh aplikasi
z.config(z.locales.id());

const envSchema = z.object({
  NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
  PORT: z.coerce.number().int().min(1).max(65535).default(3000),
  DATABASE_URL: z.string({ error: "wajib diisi, contoh: file:./dev.db" }).min(1, "wajib diisi, contoh: file:./dev.db"),
  // "*" = semua origin boleh; selain itu daftar origin dipisah koma
  CORS_ORIGIN: z
    .string()
    .default("*")
    .transform((value) => (value === "*" ? "*" : value.split(",").map((origin) => origin.trim()))),
});

const parsed = envSchema.safeParse(process.env);

if (!parsed.success) {
  const masalah = parsed.error.issues
    .map((issue) => `  - ${issue.path.join(".")}: ${issue.message}`)
    .join("\n");
  console.error(`Konfigurasi environment tidak valid:\n${masalah}\nPeriksa file .env (contoh ada di .env.example).`);
  process.exit(1);
}

export const env = parsed.data;
export const isProduction = env.NODE_ENV === "production";
export const isTest = env.NODE_ENV === "test";
```

Cara kerja file ini:

- `import "dotenv/config"` membaca file `.env` dan memasukkan isinya ke `process.env`.
- `envSchema` berisi aturan untuk setiap variabel. `z.coerce.number()` mengubah teks `"3000"` menjadi angka `3000`. `.default(...)` dipakai kalau variabel tidak diisi sama sekali.
- `CORS_ORIGIN` diubah menjadi `"*"` atau array alamat. Contoh: `"a.com,b.com"` menjadi `["a.com", "b.com"]`.
- `safeParse` memeriksa `process.env`. Kalau gagal, semua masalah dicetak, lalu `process.exit(1)` menghentikan program.
- Kalau lolos, hasil yang sudah rapi di-export sebagai `env`.

Mulai sekarang, hanya file ini yang boleh membaca `process.env`. File lain meng-import `env` yang tipenya sudah benar. Baris `z.config(z.locales.id())` juga pindah ke sini dari `src/schemas.js`, karena `env.js` adalah file proyek yang paling awal dimuat.

Buat juga `.env.example`. Anggap saja ini formulir contoh: kolomnya lengkap, isinya nilai contoh. File ini masuk git, sedangkan `.env` tidak:

```dotenv title=".env.example"
NODE_ENV=development
PORT=3000
DATABASE_URL="file:./dev.db"
# Untuk production isi daftar origin dipisah koma, contoh: https://kuliah.kampus.ac.id
CORS_ORIGIN="*"
```

Salin isinya ke `.env` milikmu. Kalau sebuah variabel di-set langsung di terminal, nilai dari terminal itulah yang dipakai, karena `dotenv` tidak menimpa variabel yang sudah ada.

Setelah refactor selesai nanti, coba jalankan server dengan port yang salah. Di PowerShell, baris kedua menghapus `PORT` lagi supaya terminalmu kembali normal:

<Step title="Pindahkan logger dan 404 ke folder middleware">

Kode kedua fungsi ini sama dengan yang sudah ada di `server.js`. Bedanya, sekarang masing-masing punya nama dan di-export supaya bisa di-import file lain.

```js title="src/middleware/logger.js"
export function logger(req, res, next) {
  const mulai = Date.now();
  res.on("finish", () => {
    const durasi = Date.now() - mulai;
    console.log(`${req.method} ${req.originalUrl} -> ${res.statusCode} (${durasi} ms)`);
  });
  next();
}
```

```js title="src/middleware/not-found.js"
export function notFound(req, res) {
  res.status(404).json({
    error: { message: "Route tidak ditemukan", code: "ROUTE_NOT_FOUND" },
  });
}
```

`logger` mencatat setiap request setelah responsnya selesai dikirim (event `finish`). `notFound` membalas 404 untuk URL yang tidak cocok dengan route mana pun.

<Step title="Modul tasks: schemas">

Schema (aturan bentuk data) tugas dipindah dari `src/schemas.js` tanpa diubah, termasuk `TASK_SORTS` dan `listTasksQuerySchema` dari pelajaran pagination. Satu-satunya perubahan: `idParamsSchema` diganti nama menjadi `taskIdParamsSchema`. Setiap modul punya schema `:id` sendiri supaya tidak bergantung pada modul lain.

```js title="src/modules/tasks/tasks.schemas.js"
import { z } from "zod";

const title = z
  .string({
    error: (issue) => (issue.input === undefined ? "Judul wajib diisi" : "Judul harus berupa teks"),
  })
  .trim()
  .min(3, "Judul minimal 3 karakter")
  .max(100, "Judul maksimal 100 karakter");

const priority = z.enum(["rendah", "sedang", "tinggi"], {
  error: "Prioritas harus rendah, sedang, atau tinggi",
});

const done = z.boolean({ error: "done harus true atau false" });

const courseId = z
  .number({ error: "courseId harus berupa angka" })
  .int("courseId harus bilangan bulat")
  .positive("courseId harus lebih dari 0")
  .nullable();

export const taskIdParamsSchema = z.object({
  id: z.coerce
    .number({ error: "id harus berupa angka" })
    .int("id harus bilangan bulat")
    .positive("id harus lebih dari 0"),
});

export const TASK_SORTS = ["createdAt", "-createdAt", "title", "priority"];

export const listTasksQuerySchema = z.object({
  page: z.coerce
    .number({ error: "page harus berupa angka" })
    .int("page harus bilangan bulat")
    .min(1, "page minimal 1")
    .default(1),
  limit: z.coerce
    .number({ error: "limit harus berupa angka" })
    .int("limit harus bilangan bulat")
    .min(1, "limit minimal 1")
    .max(50, "limit maksimal 50")
    .default(10),
  done: z
    .stringbool({ truthy: ["true"], falsy: ["false"], error: "done harus true atau false" })
    .optional(),
  priority: priority.optional(),
  courseId: z.coerce
    .number({ error: "courseId harus berupa angka" })
    .int("courseId harus bilangan bulat")
    .positive("courseId harus lebih dari 0")
    .optional(),
  q: z.string({ error: "q harus berupa teks" }).trim().max(100, "q maksimal 100 karakter").optional(),
  sort: z
    .enum(TASK_SORTS, { error: `sort harus salah satu dari: ${TASK_SORTS.join(", ")}` })
    .default("-createdAt"),
});

export const createTaskSchema = z.object({
  title,
  priority: priority.optional(),
  done: done.optional(),
  courseId: courseId.optional(),
});

export const replaceTaskSchema = z.object({
  title,
  done,
  priority: priority.default("sedang"),
```

Ada tiga schema untuk body: `createTaskSchema` untuk POST, `replaceTaskSchema` untuk PUT (data wajib lengkap), dan `updateTaskSchema` untuk PATCH (boleh sebagian).

<Step title="Modul tasks: service">

Semua kode Prisma pindah ke file ini, termasuk peta `TASK_ORDER_BY` dari pelajaran pagination. Coba cari `req` atau `res` di file ini. Tidak ada satu pun.

```js title="src/modules/tasks/tasks.service.js"
import { HttpError } from "../../lib/http-error.js";
import { prisma } from "../../lib/prisma.js";

const TASK_ORDER_BY = {
  createdAt: [{ createdAt: "asc" }, { id: "asc" }],
  "-createdAt": [{ createdAt: "desc" }, { id: "desc" }],
  title: [{ title: "asc" }, { id: "asc" }],
  priority: [{ priority: "asc" }, { id: "asc" }],
};

export async function listTasks({ page, limit, done, priority, courseId, q, sort }) {
  const where = {
    done,
    priority,
    courseId,
    title: q ? { contains: q } : undefined,
  };

  const [tasks, total] = await prisma.$transaction([
    prisma.task.findMany({
      where,
      orderBy: TASK_ORDER_BY[sort],
      skip: (page - 1) * limit,
      take: limit,
    }),
    prisma.task.count({ where }),
  ]);

  return {
    data: tasks,
    meta: { page, limit, total, totalPages: Math.ceil(total / limit) },
  };
}

export async function getTask(id) {
  const task = await prisma.task.findUnique({ where: { id }, include: { course: true } });
  if (!task) throw HttpError.notFound("Tugas tidak ditemukan");
  return task;
}

export function createTask(input) {
  return prisma.task.create({ data: input });
}

// Dipakai PUT dan PATCH: bedanya hanya di schema validasi
export function updateTask(id, input) {
  return prisma.task.update({ where: { id }, data: input });
}

export async function deleteTask(id) {
  await prisma.task.delete({ where: { id } });
}
```

Isi file ini dalam bahasa sehari-hari:

- `listTasks` menerima objek filter biasa. Lewat `$transaction`, ia menjalankan dua query dalam satu paket: mengambil satu halaman tugas dan menghitung totalnya.
- `getTask` melempar `HttpError.notFound` kalau tugasnya tidak ada.
- `createTask`, `updateTask`, dan `deleteTask` masing-masing cukup satu panggilan Prisma.

Service tidak peduli request datang lewat PUT atau PATCH. Aturan "wajib lengkap" atau "boleh sebagian" adalah urusan HTTP, jadi sudah ditangani schema di lapisan validasi.

</Step>
<Step title="Modul tasks: routes">

`express.Router()` membuat "mini-app" yang punya daftar route sendiri. Bayangkan gedung kampus. Di lobi ada papan "Tugas: lantai 2". Di lantai 2 cukup ditulis "Ruang 1, Ruang 2", karena semua orang tahu ini lantai tugas. Path di dalam router juga begitu: dihitung dari tempat router dipasang, jadi cukup `/` dan `/:id`.

```js title="src/modules/tasks/tasks.routes.js"
import express from "express";
import { validate } from "../../middleware/validate.js";
import {
  createTaskSchema,
  listTasksQuerySchema,
  replaceTaskSchema,
  taskIdParamsSchema,
  updateTaskSchema,
} from "./tasks.schemas.js";
import * as tasksService from "./tasks.service.js";

export const tasksRouter = express.Router();

tasksRouter.get("/", validate({ query: listTasksQuerySchema }), async (req, res) => {
  res.json(await tasksService.listTasks(req.query));
});

tasksRouter.get("/:id", validate({ params: taskIdParamsSchema }), async (req, res) => {
  const task = await tasksService.getTask(req.params.id);
  res.json({ data: task });
});

tasksRouter.post("/", validate({ body: createTaskSchema }), async (req, res) => {
  const task = await tasksService.createTask(req.body);
  res.status(201).json({ data: task });
});

tasksRouter.put(
  "/:id",
  validate({ params: taskIdParamsSchema, body: replaceTaskSchema }),
  async (req, res) => {
    const task = await tasksService.updateTask(req.params.id, req.body);
    res.json({ data: task });
  },
);

tasksRouter.patch(
  "/:id",
  validate({ params: taskIdParamsSchema, body: updateTaskSchema }),
  async (req, res) => {
    const task = await tasksService.updateTask(req.params.id, req.body);
    res.json({ data: task });
  },
);

tasksRouter.delete("/:id", validate({ params: taskIdParamsSchema }), async (req, res) => {
  await tasksService.deleteTask(req.params.id);
  res.status(204).end();
});
```

`import * as tasksService` mengumpulkan semua export service dalam satu objek, sehingga di handler terbaca jelas: `tasksService.getTask(...)`. Semua route mengikuti pola yang sama: `validate(...)` memeriksa input dulu, lalu handler memanggil satu fungsi service dan mengirim hasilnya.

</Step>

File `app.js` adalah tempat semua bagian dipasang menjadi satu aplikasi.

```js title="src/app.js" showLineNumbers
import cors from "cors";
import express from "express";
import helmet from "helmet";
import { env, isTest } from "./config/env.js";
import { errorHandler } from "./middleware/error-handler.js";
import { logger } from "./middleware/logger.js";
import { notFound } from "./middleware/not-found.js";
import { coursesRouter } from "./modules/courses/courses.routes.js";
import { tasksRouter } from "./modules/tasks/tasks.routes.js";

// Membuat app tanpa listen(), supaya bisa dipakai server.js maupun test
export function createApp() {
  const app = express();

  if (!isTest) app.use(logger);
  app.use(helmet());
  app.use(cors({ origin: env.CORS_ORIGIN }));
  app.use(express.json());

  app.get("/api/health", (req, res) => {
    res.json({ data: { status: "ok" } });
  });
  app.use("/api/tasks", tasksRouter);
  app.use("/api/courses", coursesRouter);

  // Urutan penting: 404 setelah semua route, error handler paling akhir
  app.use(notFound);
  app.use(errorHandler);

  return app;
}
```

Baca dari atas ke bawah. Urutannya sama dengan urutan request diproses:

- Baris 15–18: middleware global. Logger (dilewati saat test), helmet, cors, lalu `express.json()` yang membaca body JSON.
- Baris 20–24: health check dan dua router.
- Baris 27–28: `notFound` untuk URL yang tidak cocok dengan route mana pun, lalu error handler paling akhir.

`app.use("/api/tasks", tasksRouter)` memasang router di prefix `/api/tasks`. Request `GET /api/tasks/7` masuk ke router sebagai `GET /7` dan cocok dengan `tasksRouter.get("/:id", ...)`.

<Step title="Kecilkan server.js">

Sekarang `server.js` hanya punya dua tugas: menyalakan server, lalu mematikannya dengan rapi saat diminta. Cara mematikan yang rapi ini disebut **graceful shutdown**.

<Callout type="analogi" title="Seperti warung yang mau tutup">

Warung yang tutup dengan rapi tidak langsung mematikan kompor. Pemilik membalik papan menjadi "Tutup" supaya tidak ada pembeli baru. Pembeli yang sudah memesan tetap dilayani sampai selesai. Setelah itu baru gas dimatikan.

- membalik papan "Tutup" = `server.close()` (berhenti menerima koneksi baru)
- melayani pembeli yang tersisa = menunggu request yang sedang berjalan
- mematikan gas = `prisma.$disconnect()` (menutup koneksi database)

</Callout>

Seluruh isi `src/server.js` diganti menjadi file pendek ini:

```js title="src/server.js"
import { createApp } from "./app.js";
import { env } from "./config/env.js";
import { prisma } from "./lib/prisma.js";

const app = createApp();

const server = app.listen(env.PORT, (error) => {
  if (error) throw error;
  console.log(`Server jalan di http://localhost:${env.PORT} (${env.NODE_ENV})`);
});

// Graceful shutdown: selesaikan request yang berjalan, tutup database, baru keluar
function shutdown(signal) {
  console.log(`${signal} diterima, menutup server...`);
  server.close(async () => {
    await prisma.$disconnect();
    console.log("Server berhenti dengan rapi");
    process.exit(0);
  });
}

process.on("SIGINT", shutdown);
process.on("SIGTERM", shutdown);
```

`SIGINT` dan `SIGTERM` adalah sinyal dari sistem operasi yang artinya "tolong berhenti". `SIGINT` dikirim saat kamu menekan <Kbd>Ctrl</Kbd> + <Kbd>C</Kbd>. `SIGTERM` dikirim platform hosting saat server dihentikan atau di-deploy ulang. Keduanya menjalankan `shutdown`. Tanpa graceful shutdown, request yang sedang menyimpan tugas bisa terputus di tengah jalan.

</Step>
</Steps>

## CORS dan helmet

<Callout type="analogi" title="Seperti satpam asrama">

Kamu tinggal di asrama dan menitip surat lewat satpam ke sebuah kantor. Balasannya datang ke pos satpam. Satpam hanya menyerahkan balasan itu kalau amplopnya diberi cap "boleh diberikan ke penghuni asrama ini". Tanpa cap, balasan ditahan. Untuk urusan tertentu, satpam bahkan menelepon kantor dulu untuk bertanya boleh atau tidak.

- kamu = JavaScript di halaman web (misalnya Expo Web di `localhost:8081`)
- satpam = browser
- kantor = API di `localhost:3000`
- cap di amplop = header `Access-Control-Allow-Origin`
- telepon dulu = request *preflight*

Aplikasi di HP dan `curl` tidak tinggal di asrama itu, jadi tidak melewati satpam sama sekali.

</Callout>

Browser punya aturan keamanan bernama **same-origin policy**. Origin adalah gabungan protokol, alamat, dan port, misalnya `http://localhost:8081`. Menurut aturan ini, JavaScript di halaman `http://localhost:8081` (Expo Web) tidak boleh membaca respons dari `http://localhost:3000`, kecuali server mengizinkannya.

Izin itu dikirim lewat header `Access-Control-Allow-Origin`. Mekanismenya disebut [CORS](/glosarium#cors) (Cross-Origin Resource Sharing). Paket `cors` menambahkan header tersebut untukmu. Paket ini juga menjawab request *preflight*, yaitu request `OPTIONS` yang dikirim browser untuk minta izin dulu sebelum `PATCH` atau `DELETE`.

Tanpa CORS, Console browser menampilkan:

```txt
Access to fetch at 'http://localhost:3000/api/tasks' from origin 'http://localhost:8081' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

[Helmet](/glosarium#helmet) mirip memasang kunci tambahan dan tirai di kamar kos. Isi kamarnya tidak berubah, hanya celahnya yang ditutup. Helmet menambahkan belasan header keamanan sekaligus. Contohnya `X-Content-Type-Options: nosniff`, supaya browser tidak menebak-nebak tipe file. Helmet juga menghapus header `X-Powered-By: Express` yang memberi tahu orang luar teknologi servermu.

Cek hasilnya dengan `curl`. Opsi `-i` menampilkan header respons, dan `-H` menambahkan header `Origin` seolah request datang dari Expo Web:

<Tabs items={["Windows (PowerShell)", "macOS / Linux"]}>
<Tab>

```powershell
curl.exe -i -H "Origin: http://localhost:8081" http://localhost:3000/api/health
```

</Tab>
<Tab>

```bash
curl -i -H "Origin: http://localhost:8081" http://localhost:3000/api/health
```

</Tab>
</Tabs>

```http
Content-Security-Policy: default-src 'self';base-uri 'self';font-src 'self' https: data:;form-action 'self';frame-ancestors 'self';img-src 'self' data:;object-src 'none';script-src 'self';script-src-attr 'none';style-src 'self' https: 'unsafe-inline';upgrade-insecure-requests
```

<Callout type="info" title="Aplikasi HP tidak terkena CORS">

CORS adalah aturan browser. Aplikasi Expo yang berjalan di HP atau emulator memanggil API tanpa pemeriksaan CORS, begitu juga `curl`. Jadi CORS tidak melindungi API-mu dari siapa pun. CORS hanya memberi izin kepada halaman web dari origin lain. Untuk development, `CORS_ORIGIN="*"` aman dan praktis. Di production, isi dengan alamat web aplikasimu saja.

</Callout>

## Logging request

<Callout type="analogi" title="Seperti buku tamu satpam">

Satpam kampus mencatat setiap tamu di buku tamu: jam datang, tujuan, dan jam pulang. Isi tas tamu tidak ikut ditulis. Kalau ada laporan barang hilang, buku itulah yang pertama kali dibuka.

Logger-mu melakukan hal yang sama untuk setiap request: method, URL, status, dan durasi. Isi body, seperti isi tas tamu, tidak dicatat.

</Callout>

[Logging](/glosarium#logging) adalah mencatat apa yang terjadi di server. Saat pengguna melapor "tadi gagal simpan", log menunjukkan request apa yang datang, status apa yang dikirim, dan berapa lama prosesnya.

Tiga aturan yang berlaku di proyek mana pun:

- **Jangan log isi body atau header `Authorization`.** Di Track 3, body bisa berisi password dan header bisa berisi token.
- **Log error lengkap hanya di server.** Error handler sudah melakukannya dengan `console.error(err)`, sementara client hanya mendapat pesan umum.
- **Matikan log yang tidak perlu.** Di `createApp()`, logger dilewati saat `NODE_ENV=test`, supaya output test tidak penuh baris request.

Proyek besar biasanya memakai library seperti `morgan` atau `pino` (log berformat JSON). API pendamping memakai `morgan("dev")`, yang hasilnya mirip logger buatanmu.

## Integration test pertama

Karena `createApp()` tidak memanggil `listen`, kamu bisa mengujinya langsung. [Integration test](/glosarium#integration-test) adalah test yang menguji beberapa lapisan sekaligus: route, validasi, service, dan database. Mirip juru masak yang mencicipi hidangan utuh di dapur sebelum warung dibuka, bukan mencicipi nasi dan sambal satu per satu. Kamu butuh dua alat:

- **Supertest** menyalakan app di port acak sementara, mengirim request HTTP, lalu mematikannya lagi.
- **`node:test`** adalah test runner (alat yang menjalankan test dan melaporkan hasilnya) bawaan Node. Jadi tidak perlu memasang Jest atau Vitest.

```bash
npm install --save-dev supertest
```

Buat file `.env.test` berisi satu baris `NODE_ENV=test`, lalu tulis test-nya:

```js title="tests/app.test.js"
import assert from "node:assert/strict";
import { after, test } from "node:test";
import request from "supertest";
import { createApp } from "../src/app.js";
import { prisma } from "../src/lib/prisma.js";

const app = createApp();

after(() => prisma.$disconnect());

test("GET /api/health membalas status ok", async () => {
  const res = await request(app).get("/api/health");
  assert.equal(res.status, 200);
  assert.deepEqual(res.body, { data: { status: "ok" } });
});

test("route asing dibalas 404 ROUTE_NOT_FOUND", async () => {
  const res = await request(app).get("/api/tidak-ada");
  assert.equal(res.status, 404);
  assert.equal(res.body.error.code, "ROUTE_NOT_FOUND");
});

test("POST /api/tasks dengan judul terlalu pendek dibalas 400", async () => {
  const res = await request(app).post("/api/tasks").send({ title: "ab" });
  assert.equal(res.status, 400);
  assert.equal(res.body.error.code, "VALIDATION_ERROR");
  assert.deepEqual(res.body.error.details, [{ field: "title", message: "Judul minimal 3 karakter" }]);
});

test("GET /api/tasks memakai format { data, meta }", async () => {
  const res = await request(app).get("/api/tasks?limit=2");
  assert.equal(res.status, 200);
  assert.ok(Array.isArray(res.body.data));
  assert.ok(res.body.data.length <= 2);
  assert.equal(res.body.meta.limit, 2);
});
```

Cara membaca test di atas:

- `test("nama", fungsi)` mendefinisikan satu test. Namanya ditulis seperti kalimat, supaya laporan hasilnya mudah dibaca.
- `request(app).get(...)` mengirim request ke app. `.send(objek)` otomatis mengirim JSON beserta header `Content-Type`-nya.
- `assert.equal(a, b)` membuat test gagal kalau `a` tidak sama dengan `b`. `assert.deepEqual` membandingkan isi objek sampai ke dalam.
- Hook `after` menutup koneksi Prisma setelah semua test selesai.

Tiga test pertama tidak menyentuh database. Test keempat membaca `dev.db`, jadi jalankan `npx prisma db seed` lebih dulu. Di [Testing Backend](/belajar/expert/testing-backend) kamu akan belajar memakai database khusus test, supaya test boleh menulis data tanpa merusak data development.

## Ringkasan

- Refactor mengubah susunan kode tanpa mengubah perilakunya. Buktinya: semua request lama tetap memberi respons yang sama.
- Urutan lapisan `belajar-api`: route → `validate()` → handler (controller) → service → Prisma. Service tidak menyentuh `req`/`res`, dan handler tidak menulis query.
- Folder per fitur (`src/modules/tasks`, `src/modules/courses`) menyimpan routes, service, dan schema satu fitur di satu tempat. Kode bersama tinggal di `lib/` dan `middleware/`.
- `src/config/env.js` memeriksa environment variable dengan Zod sekali saat server start (fail fast). `.env` tetap rahasia, `.env.example` masuk git.
- `cors` memberi izin kepada halaman web dari origin lain. `helmet` menambah header keamanan. Logger mencatat method, URL, status, dan durasi tanpa data sensitif.
- `createApp()` di `src/app.js` dipisah dari `listen()`, jadi app bisa diuji dengan `node:test` + Supertest. `server.js` hanya menyalakan server dan menutupnya dengan rapi saat `SIGINT`/`SIGTERM`.
