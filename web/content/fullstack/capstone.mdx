### User story

**User story** adalah kalimat pendek yang menjelaskan keinginan pengguna dari sudut pandang mereka. Polanya "Sebagai ..., saya ingin ..., supaya ...". Bagian "supaya" penting karena menjelaskan alasan fitur itu dibuat.

1. Sebagai mahasiswa, saya ingin **mendaftar dan login** supaya tugas saya tidak tercampur dengan tugas orang lain.
2. Sebagai mahasiswa, saya ingin **mengelola mata kuliah** (nama, kode, dosen, warna) supaya tugas bisa dikelompokkan.
3. Sebagai mahasiswa, saya ingin **memilih mata kuliah saat membuat tugas** supaya tidak perlu mengetik ulang namanya.
4. Sebagai mahasiswa, saya ingin **memfilter dan mencari tugas** supaya cepat menemukan tugas "Basis Data" yang belum selesai.
5. Sebagai mahasiswa, saya ingin **melihat tanda tenggat** (terlambat, hari ini, besok) supaya tidak ada tugas yang terlewat.
6. Sebagai mahasiswa, saya ingin **melampirkan foto** (misalnya papan tulis atau soal) ke sebuah tugas.
7. Sebagai mahasiswa, saya ingin **melihat profil dan keluar** dari akun, terutama saat meminjam HP teman.

## Navigasi tab

Sampai pelajaran Upload Gambar, semua layar hidup di satu **Stack**. Stack adalah cara navigasi yang menumpuk layar: layar baru diletakkan di atas layar lama, dan tombol kembali mengangkatnya lagi. Daftar tugas ada di `src/app/index.js`, dan pengguna pindah layar hanya lewat tombol.

Sekarang kita butuh tiga **tab**, yaitu tombol pindah halaman di bagian bawah layar. Namun layar detail dan form tetap harus tampil menutupi tab bar, lengkap dengan tombol kembali.

### Root layout tetap menjaga pintu

Root layout adalah `src/app/_layout.js`, bingkai paling luar yang membungkus semua layar. Dari versi pelajaran Autentikasi, file ini hanya perlu dua perubahan:

1. Layar yang dilindungi sekarang cukup satu grup, yaitu `(app)`.
2. Kita memasang `ThemeProvider` untuk mode gelap. Bagian ini dibahas di Polish.

```jsx title="src/app/_layout.js"
import { useColorScheme } from "react-native";
import { QueryClientProvider } from "@tanstack/react-query";
import { DarkTheme, DefaultTheme, Stack, ThemeProvider } from "expo-router";
import { queryClient } from "../lib/query-client";
import { AuthProvider, useAuth } from "../features/auth/auth-context";

function RootNavigator() {
  const { isLoggedIn, isLoading } = useAuth();

  // Selama token di SecureStore belum selesai dibaca, jangan tampilkan apa pun
  if (isLoading) return null;

  return (
    <Stack screenOptions={{ headerShown: false }}>
      <Stack.Protected guard={isLoggedIn}>
        <Stack.Screen name="(app)" />
      </Stack.Protected>
      <Stack.Protected guard={!isLoggedIn}>
        <Stack.Screen name="(auth)" />
      </Stack.Protected>
    </Stack>
  );
}

export default function RootLayout() {
  const scheme = useColorScheme();

  return (
    <QueryClientProvider client={queryClient}>
      <AuthProvider>
        <ThemeProvider value={scheme === "dark" ? DarkTheme : DefaultTheme}>
          <RootNavigator />
        </ThemeProvider>
      </AuthProvider>
    </QueryClientProvider>
  );
}
```

Cara membaca kode di atas:

- `RootNavigator` menunggu sampai token selesai dibaca dari SecureStore. Selama menunggu, layar dibiarkan kosong.
- `Stack.Protected` bekerja seperti satpam di pintu grup. Properti `guard` adalah syarat masuknya. Nilai `true` membuka grup, `false` menutupnya.
- Grup `(app)` hanya terbuka kalau sudah login. Grup `(auth)` (Login dan Daftar) hanya terbuka kalau belum login.
- `RootLayout` membungkus semuanya dengan penyedia cache (`QueryClientProvider`), data login (`AuthProvider`), dan tema warna (`ThemeProvider`).

Kalau di pelajaran Autentikasi kamu memakai nama lain untuk hook atau status (misalnya `isSignedIn`), pakai nama milikmu. Yang penting polanya sama. Saat `isLoggedIn` berubah menjadi `false`, Expo Router otomatis membuang layar `(app)` dari riwayat dan menampilkan `(auth)`.

## CRUD mata kuliah

API pendamping sudah menyediakan **endpoint** mata kuliah sejak awal. Endpoint adalah alamat tujuan request, mirip nomor loket di kantor pelayanan. Selama ini kita hanya membaca daftar mata kuliah untuk pemilih di form tugas. Sekarang kita pakai semua fitur CRUD-nya: tambah, lihat, ubah, dan hapus.

| Method | Path | Catatan |
| --- | --- | --- |
| `GET` | `/api/courses?limit=50` | Diurutkan berdasarkan nama, maksimal 50, setiap item punya `taskCount` |
| `GET` | `/api/courses/:id` | 404 "Mata kuliah tidak ditemukan" kalau bukan milikmu |
| `POST` | `/api/courses` | `name` wajib; `code`, `lecturer`, `color` opsional |
| `PATCH` | `/api/courses/:id` | Sebagian: kirim kolom yang berubah saja |
| `DELETE` | `/api/courses/:id` | 204; tugas di dalamnya **tidak** ikut terhapus, `courseId`-nya menjadi `null` |

Ada dua aturan validasi server yang perlu kamu ingat:

1. `code` dan `lecturer` boleh berupa string kosong. Server menyimpannya sebagai `null` (kosong). Jadi, mengirim `""` adalah cara resmi untuk mengosongkan kolom itu saat mengubah data.
2. `color` harus berformat `#RRGGBB`, misalnya `#4F46E5`. Kalau formatnya salah, server membalas status 400 dengan pesan "Warna harus berformat #RRGGBB, contoh #4F46E5" di `details`.

Supaya mudah dibayangkan, anggap setiap mata kuliah adalah stiker warna bertuliskan namanya, misalnya stiker biru "Basis Data". Stiker itu ditempel di lembar-lembar tugas. Kalau stiker biru dihapus dari daftar mata kuliah, lembar tugasnya tidak ikut dibuang. Lembar itu hanya tidak berstiker lagi (`courseId` menjadi `null`).

### Query key dan hook

**Query key** adalah label laci tempat TanStack Query menyimpan hasil request di **cache** (salinan data di memori HP supaya tidak perlu minta ulang ke server). Ikuti pola `taskKeys` dari pelajaran TanStack Query: satu objek pembuat key, lalu satu hook untuk setiap operasi.

```js title="src/features/courses/queries.js"
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import { apiFetch } from "../../lib/api";
import { taskKeys } from "../tasks/queries";

export const courseKeys = {
  all: ["courses"],
  lists: () => [...courseKeys.all, "list"],
  details: () => [...courseKeys.all, "detail"],
  detail: (id) => [...courseKeys.details(), id],
};

export function useCourses() {
  return useQuery({
    queryKey: courseKeys.lists(),
    queryFn: ({ signal }) => apiFetch("/api/courses?limit=50", { signal }),
    select: (json) => json.data,
    staleTime: 5 * 60 * 1000,
  });
}

export function useCourse(id) {
  const queryClient = useQueryClient();
  return useQuery({
    queryKey: courseKeys.detail(id),
    queryFn: async ({ signal }) => {
      const json = await apiFetch(`/api/courses/${id}`, { signal });
      return json.data;
    },
    enabled: Number.isInteger(id),
    // Cache daftar menyimpan amplop { data, meta }, karena select hanya mengubah keluaran hook
    placeholderData: () =>
      queryClient.getQueryData(courseKeys.lists())?.data?.find((course) => course.id === id),
  });
}

export function useCreateCourse() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: async (input) => {
      const json = await apiFetch("/api/courses", { method: "POST", body: input });
      return json.data;
    },
    onSuccess: () => queryClient.invalidateQueries({ queryKey: courseKeys.lists() }),
  });
}

export function useUpdateCourse() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: async ({ id, input }) => {
      const json = await apiFetch(`/api/courses/${id}`, { method: "PATCH", body: input });
      return json.data;
    },
    onSuccess: (course) => {
      queryClient.setQueryData(courseKeys.detail(course.id), course);
      queryClient.invalidateQueries({ queryKey: taskKeys.all });
      return queryClient.invalidateQueries({ queryKey: courseKeys.lists() });
    },
  });
}

export function useDeleteCourse() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (id) => apiFetch(`/api/courses/${id}`, { method: "DELETE" }),
    onSuccess: (_result, id) => {
      queryClient.removeQueries({ queryKey: courseKeys.detail(id) });
      queryClient.invalidateQueries({ queryKey: taskKeys.all });
      return queryClient.invalidateQueries({ queryKey: courseKeys.lists() });
    },
  });
}
```

Isi file ini dalam bahasa sehari-hari:

- `useCourses` mengambil daftar mata kuliah. `select: (json) => json.data` membuat komponen langsung menerima array. Cache tetap menyimpan "amplop" lengkap `{ data, meta }`. Itu sebabnya `useCourse` membaca `?.data?.find(...)`.
- `useCourse` mengambil satu mata kuliah. **`placeholderData`** adalah data sementara yang ditampilkan selama data asli dimuat. Di sini datanya diambil dari daftar yang sudah ada di cache, jadi form ubah langsung terisi.
- `staleTime` lima menit artinya data dianggap masih segar selama lima menit. Mata kuliah jarang berubah, paling di awal semester. Tidak perlu minta ulang setiap kali form tugas dibuka.
- `enabled: Number.isInteger(id)` mencegah request yang pasti gagal. Parameter dari URL selalu berupa teks. Layar ubah mengubahnya dengan `Number(id)`. Kalau hasilnya `NaN` (bukan angka), query tidak dijalankan.
- Setelah ubah dan hapus, cache tugas ikut di-**invalidasi**, yaitu ditandai basi supaya diambil ulang. Alasannya, setiap tugas dari API membawa objek `course` berisi nama dan warna. Kalau warna "Basis Data" diganti, kartu tugas di cache masih membawa warna lama. Setelah hapus, tugas-tugas itu malah berubah menjadi tanpa mata kuliah.
- Hanya invalidasi daftar mata kuliah yang di-`return`. TanStack Query menunggu janji (promise) yang dikembalikan `onSuccess` sebelum `mutateAsync` selesai. Jadi daftar mata kuliah sudah segar saat layar kembali. Daftar tugas boleh menyusul di belakang.

Kenapa tidak **optimistis** seperti hapus tugas? Optimistis artinya layar langsung berubah sebelum server menjawab, lalu dibatalkan kalau gagal. Form mata kuliah cukup sering ditolak validasi, dan perubahannya jarang. Menunggu jawaban server sekitar 100 ms lebih masuk akal daripada menampilkan data yang lalu harus dibatalkan. Pola optimistis cocok untuk aksi yang sering dan hampir pasti berhasil, seperti mencentang tugas selesai.

### Form mata kuliah

Form ini lebih kecil dari form tugas, tetapi polanya sama:

1. State menyimpan nilai setiap kolom.
2. Validasi ringan dijalankan di HP sebelum mengirim.
3. Pesan error dari server (`details`) dipetakan ke kolom yang tepat.

export function courseToValues(course) {
  return {
    name: course.name,
    code: course.code ?? "",

export function toCoursePayload(values) {
  return {

function toCourseErrors(error) {
  if (error instanceof ApiError && error.code === "VALIDATION_ERROR") {
    const fieldErrors = {};
    for (const { field, message } of error.details ?? []) fieldErrors[field] ??= message;
    return { fieldErrors, formError: Object.keys(fieldErrors).length ? null : error.message };
  }
  return { fieldErrors: {}, formError: error.message };
}

export function CourseForm({ initialValues = EMPTY_COURSE_VALUES, submitLabel = "Simpan", onSubmit }) {
  const [values, setValues] = useState(initialValues);
  const [errors, setErrors] = useState({});
  const [formError, setFormError] = useState(null);
  const [saving, setSaving] = useState(false);

  function setField(name, value) {
    setValues((prev) => ({ ...prev, [name]: value }));
    setErrors((prev) => ({ ...prev, [name]: undefined }));
  }

  async function handleSubmit() {
    if (saving) return;
    if (!values.name.trim()) {
      setErrors({ name: "Nama mata kuliah wajib diisi" });

        onChangeText={(text) => setField("name", text)}

        placeholder="Basis Data"

      <TextField
        label="Kode (opsional)"
        value={values.code}
        onChangeText={(text) => setField("code", text)}
        error={errors.code}

        autoCapitalize="characters"
      />

        label="Dosen (opsional)"

              key={color}
              onPress={() => setField("color", color)}
              accessibilityRole="radio"
              accessibilityLabel={`Warna ${color}`}
              accessibilityState={{ checked: selected }}
              hitSlop={4}

          );
        })}
      </View>

Bagian penting dari form ini:

- `courseToValues` dan `toCoursePayload` adalah penerjemah. Yang pertama mengubah data server menjadi isi form. Yang kedua mengubah isi form menjadi **payload**, yaitu isi request yang dikirim ke server.
- `toCourseErrors` membaca error validasi dari server, lalu menaruh pesannya di kolom yang sesuai, misalnya di bawah kolom Nama.
- `handleSubmit` menolak nama kosong sebelum mengirim. Kalau server menolak, pesan error ditampilkan dan tombol bisa ditekan lagi.

`toCoursePayload` selalu mengirim `code` dan `lecturer` sebagai string, termasuk string kosong. Untuk `POST`, server mengubahnya menjadi `null`. Untuk `PATCH`, string kosong berarti "hapus kode ini". Karena itu kolom kosong tidak dibuang dari payload. Kalau dibuang, pengguna tidak akan pernah bisa menghapus nama dosen yang salah ketik.

Pilihan warna dibatasi ke delapan **swatch** (lingkaran contoh warna) supaya format warnanya pasti benar. Swatch berukuran 40 px dengan `hitSlop={4}`, jadi area sentuhnya 48 px, cukup untuk jempol. Validasi warna di server tetap berguna. Kamu akan memakainya di Latihan 3.

## Filter, pencarian, dan urutan tugas

Dengan 10 tugas contoh, daftar masih bisa diperiksa dengan mata. Di akhir semester bisa ada 60 tugas, dan Andi butuh cara mempersempitnya. API sudah mendukung semua yang kita perlukan lewat [query string](/glosarium#query-string) `GET /api/tasks`. Query string adalah tambahan setelah tanda `?` di URL, misalnya `?status=DONE`.

| Parameter | Contoh | Arti |
| --- | --- | --- |
| `status` | `TODO`, `IN_PROGRESS`, `DONE` | Hanya tugas dengan status itu |
| `courseId` | `3` | Hanya tugas mata kuliah tertentu |
| `q` | `erd` | Cari di judul dan deskripsi (maksimal 100 karakter) |
| `sort` | `deadline`, `-createdAt` | Urutan; `deadline` menaruh tugas tanpa tenggat di paling bawah |

Ingat `toQueryString` dari pelajaran TanStack Query. Fungsi itu membuang nilai `undefined`, `null`, dan string kosong. Jadi pilihan "Semua" cukup diwakili `undefined`, dan parameter itu tidak ikut terkirim.

### Debounce pencarian

Kalau setiap huruf yang diketik langsung mengubah filter, mengetik "basis" mengirim lima request. Selain boros, jawabannya bisa tiba tidak berurutan. **Debounce** menunda pembaruan sampai pengguna berhenti mengetik sebentar.

<Callout type="analogi" title="Seperti pintu lift">

Pintu lift tidak langsung menutup saat satu orang masuk. Lift menunggu beberapa detik. Kalau ada orang lain masuk, hitungan waktunya diulang dari awal. Pintu baru menutup setelah tidak ada yang masuk lagi. Debounce bekerja sama: setiap huruf baru mengulang hitungan 400 ms, dan request baru dikirim setelah jarimu diam.

</Callout>

```js title="src/lib/use-debounced-value.js"
import { useEffect, useState } from "react";

export function useDebouncedValue(value, delayMs = 400) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(timer);
  }, [value, delayMs]);

  return debounced;
}
```

Cara kerjanya:

- Setiap kali `value` berubah, `useEffect` memasang timer baru selama 400 ms.
- Sebelum timer baru dipasang, fungsi cleanup (`clearTimeout`) membatalkan timer lama.
- Nilai baru hanya diteruskan kalau tidak ada perubahan selama 400 ms.

Simulasinya saat Sari mengetik "erd" dengan jeda 150 ms per huruf:

```txt
t=0     ketik "e"    -> timer A dipasang (400 ms)
t=150   ketik "er"   -> timer A dibatalkan, timer B dipasang
t=300   ketik "erd"  -> timer B dibatalkan, timer C dipasang
t=700   timer C jalan -> debounced = "erd" -> satu request: GET /api/tasks?q=erd&sort=deadline...
```

Sari mengetik tiga huruf, tetapi hanya satu request yang terkirim. Jeda 400 ms cukup pendek sehingga aplikasi tetap terasa cepat. Jeda itu juga cukup panjang untuk kecepatan mengetik jempol rata-rata.

## Badge tenggat

Kriteria K6 meminta **badge**, yaitu label kecil berwarna di kartu tugas: "Terlambat", "Hari ini", atau "Besok". Fungsinya mirip stiker merah "SEGERA" yang ditempel di map surat penting. Sekali lirik, kamu tahu mana yang harus dikerjakan dulu.

Logikanya kita pisahkan ke **fungsi murni**, yaitu fungsi yang hasilnya hanya bergantung pada masukannya. Fungsi seperti ini mudah diuji tanpa membuka aplikasi.

```js title="src/lib/deadline.js"
const DAY_MS = 24 * 60 * 60 * 1000;

function startOfDay(date) {
  const copy = new Date(date);
  copy.setHours(0, 0, 0, 0);
  return copy;
}

export function getDeadlineBadge(deadlineIso, status, now = new Date()) {
  if (!deadlineIso || status === "DONE") return null;

  const deadline = new Date(deadlineIso);
  if (deadline < now) {
    return { tone: "overdue", label: "Terlambat", color: "#B91C1C", bg: "#FEE2E2" };
  }

  const days = Math.round((startOfDay(deadline) - startOfDay(now)) / DAY_MS);
  if (days === 0) return { tone: "today", label: "Hari ini", color: "#B45309", bg: "#FEF3C7" };
  if (days === 1) return { tone: "tomorrow", label: "Besok", color: "#0369A1", bg: "#E0F2FE" };
  return null;
}
```

Cara membaca fungsi ini:

- Tugas tanpa tenggat atau yang sudah selesai tidak diberi badge. Tugas yang sudah dikumpulkan tidak "terlambat", walaupun tanggalnya lewat.
- Kalau tenggat sudah lewat dari waktu sekarang, hasilnya "Terlambat".
- "Hari ini" dan "Besok" dihitung per hari kalender, bukan per 24 jam. Tugas bertenggat besok pukul 23.59 tetap "Besok" walaupun sekarang pukul 08.00 (selisihnya hampir 40 jam). Form tugas dari pelajaran Create & Update menyimpan tenggat pukul 23.59 waktu HP. Jadi tugas bertenggat hari ini baru menjadi "Terlambat" setelah tengah malam.
- `Math.round` menutup selisih kecil kalau suatu zona waktu memakai jam musim panas. Indonesia tidak memakainya, tetapi aplikasimu mungkin dipakai teman yang kuliah di luar negeri.
- Parameter `now` bisa diisi saat menguji, sehingga hasilnya tidak bergantung pada jam komputer.

Bentuk objek yang dikembalikan sengaja sama dengan `getStatusInfo` dari `src/lib/labels.js` (`label`, `color`, `bg`), jadi bisa langsung masuk ke `Pill` yang sudah ada:

## Profil dan logout

Tab Profil menjawab pertanyaan sederhana: "Saya sedang login sebagai siapa?" Pertanyaan ini penting kalau HP dipakai bergantian. Datanya diambil dari endpoint yang dilindungi [JWT](/glosarium#jwt), yaitu token login yang dikirim di setiap request:

```http
GET /api/auth/me HTTP/1.1
Authorization: Bearer <access token>

HTTP/1.1 200 OK
Content-Type: application/json

{
  "data": {
    "id": 1,
    "name": "Mahasiswa Demo",
    "email": "demo@kampus.ac.id",
    "createdAt": "2026-08-01T02:00:00.000Z"
  }
}
```

Kenapa tidak memakai data pengguna yang dikirim saat login saja? Data itu hanya ada di memori sejak login terakhir. Setelah aplikasi ditutup dan dibuka lagi, yang tersisa hanya token di SecureStore. Membaca `/api/auth/me` juga sekaligus membuktikan token masih diterima server.

Layar Profil di bawah berisi tiga bagian. `useMe` mengambil data akun. Bagian tampilan menunjukkan nama, email, tanggal bergabung, dan jumlah mata kuliah. `handleLogout` meminta konfirmasi, lalu menjalankan proses keluar.

### Apa yang terjadi saat Keluar

<Callout type="analogi" title="Seperti pindah dari kamar kos">

Saat Andi pindah kos, ia mengembalikan kunci ke ibu kos (token dimatikan di server), lalu membuang kunci cadangan dari dompetnya (token dihapus dari SecureStore). Setelah itu kamar dibersihkan sebelum Sari masuk (`queryClient.clear()`). Kamar dibersihkan setelah Andi benar-benar keluar, bukan saat ia masih menaruh barang. Kalau dibersihkan terlalu cepat, barang Andi bisa masuk lagi ke kamar yang sudah bersih.

</Callout>

<Flow nodes={["Ketuk Keluar", "Konfirmasi", "POST /api/auth/logout", "Hapus token", "Guard berganti", "Cache dibersihkan"]} labels={["confirmAsync", "signOut()", "SecureStore", "isLoggedIn false", "queryClient.clear()"]} caption="Urutan langkah logout dari tab Profil" />

`signOut` dari pelajaran Autentikasi menjalankan tiga langkah:

1. Mengirim refresh token ke `POST /api/auth/logout`. Server membalas 204 dan mematikan token itu.
2. Menghapus kedua token dari SecureStore.
3. Mengubah `isLoggedIn` menjadi `false`.

Begitu nilainya berubah, `Stack.Protected` di root layout menutup grup `(app)` dan membuka `(auth)`. Kamu tidak perlu memanggil `router.replace("/login")` sendiri.

Pastikan `signOut` milikmu tetap menghapus token lokal walaupun request logout gagal, misalnya karena HP sedang offline. Kalau request itu melempar error dan fungsinya berhenti di tengah jalan, pengguna akan terjebak dalam keadaan login. Bungkus request-nya dengan `try/catch` kalau belum.

Lalu kenapa perlu `queryClient.clear()`? Cache TanStack Query hidup di memori selama aplikasi berjalan, dan cache tidak tahu soal akun. Tanpa `clear()`, kalau Andi keluar lalu Sari login di HP yang sama, tab Tugas milik Sari sempat menampilkan tugas Andi sebelum data baru tiba. Itu kebocoran data, walaupun hanya sesaat.

Urutannya juga penting: `clear()` dipanggil setelah `signOut`. Kalau cache dibersihkan duluan saat layar `(app)` masih terpasang, query yang masih aktif bisa langsung mengambil data lagi dengan token lama dan mengisi cache kembali.

## Polish

**Polish** artinya merapikan detail kecil supaya aplikasi enak dipakai. Semua fitur sudah ada. Bagian ini mengubah aplikasi dari "bisa jalan" menjadi "nyaman dipakai". ### Skeleton saat memuat

Spinner (ikon bulat yang berputar) hanya bilang "tunggu". **Skeleton** adalah kotak abu-abu berbentuk kartu yang berdenyut pelan. Ia juga memberi gambaran seperti apa isi yang akan datang. Mirip pelayan warung yang menata piring dan sendok sebelum makanan datang: kamu sudah tahu pesananmu akan muncul di situ. Saat data asli tiba, tata letaknya tidak melompat.

```jsx title="src/components/skeleton.js"
import { useEffect, useRef } from "react";
import { Animated, StyleSheet, View } from "react-native";

function CardShape() {
  return (
    <View style={styles.card}>
      <View style={[styles.line, { width: "70%", height: 16 }]} />
      <View style={[styles.line, { width: "40%" }]} />
      <View style={styles.pills}>
        <View style={styles.pill} />
        <View style={styles.pill} />
      </View>
    </View>
  );
}

export function SkeletonList({ count = 4 }) {
  const opacity = useRef(new Animated.Value(0.5)).current;

  useEffect(() => {
    const pulse = Animated.loop(
      Animated.sequence([
        Animated.timing(opacity, { toValue: 1, duration: 700, useNativeDriver: true }),
        Animated.timing(opacity, { toValue: 0.5, duration: 700, useNativeDriver: true }),
      ]),
    );
    pulse.start();
    return () => pulse.stop();
  }, [opacity]);

  return (
    <Animated.View
      style={[styles.list, { opacity }]}
      accessible
      accessibilityRole="progressbar"
      accessibilityLabel="Memuat daftar"
    >
      {Array.from({ length: count }, (_, i) => (
        <CardShape key={i} />
      ))}
    </Animated.View>
  );
}

const styles = StyleSheet.create({
  list: { padding: 16, gap: 12 },
  card: { borderRadius: 12, padding: 16, gap: 10, backgroundColor: "#F1F5F9" },
  line: { height: 12, borderRadius: 6, backgroundColor: "#E2E8F0" },
  pills: { flexDirection: "row", gap: 6 },
  pill: { width: 64, height: 18, borderRadius: 999, backgroundColor: "#E2E8F0" },
});
```

Cara kerja kode di atas:

- `CardShape` menggambar satu kartu palsu: dua garis abu-abu dan dua kapsul kecil.
- `opacity` adalah tingkat ketebalan tampilan. Nilainya naik turun antara 0.5 dan 1 setiap 700 milidetik, jadi kartu terlihat berdenyut.
- Satu nilai animasi dipakai bersama oleh semua kartu. Semuanya berdenyut serempak, dan hanya satu animasi yang berjalan.
- `useNativeDriver: true` menyerahkan animasi ke bagian native HP, bukan ke JavaScript. Denyutnya tetap halus walaupun JavaScript sedang sibuk mengolah respons.
- Fungsi `return` di `useEffect` menghentikan animasi saat skeleton hilang dari layar.

### ErrorBoundary untuk kesalahan tak terduga

Kadang layar gagal digambar karena error. Contohnya, kode membaca `task.course.name` padahal `course` bernilai `null`. React lalu menghentikan seluruh pohon komponen, dan di build produksi pengguna hanya melihat layar kosong. **ErrorBoundary** adalah jaring pengamannya: layar cadangan yang muncul saat ada error seperti itu. Di Expo Router, caranya cukup mengekspor fungsi bernama `ErrorBoundary` dari file rute atau layout.

```jsx title="src/app/(app)/_layout.js"
import { Pressable, StyleSheet, Text, View } from "react-native";
import { Stack } from "expo-router";

export function ErrorBoundary({ error, retry }) {
  return (
    <View style={styles.container}>
      <Text style={styles.title} accessibilityRole="header">Ada yang tidak beres</Text>
      <Text style={styles.message}>{error.message}</Text>
      <Pressable onPress={retry} accessibilityRole="button" style={styles.button}>
        <Text style={styles.buttonText}>Coba lagi</Text>
      </Pressable>
    </View>
  );
}

export default function AppLayout() {
  // ...isi Stack yang sama seperti sebelumnya
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: "center", justifyContent: "center", padding: 24, gap: 12 },
  title: { fontSize: 20, fontWeight: "700" },
  message: { color: "#64748B", textAlign: "center" },
  button: { minHeight: 48, paddingHorizontal: 24, borderRadius: 10, backgroundColor: "#4F46E5", justifyContent: "center" },
  buttonText: { color: "#FFFFFF", fontWeight: "600" },
});
```

Fungsi `ErrorBoundary` menerima dua hal: `error` (berisi pesan kesalahan) dan `retry` (fungsi untuk mencoba lagi). Karena diekspor dari layout `(app)`, ia menangkap error dari semua layar di dalamnya, termasuk ketiga tab. Tombol Coba lagi memanggil `retry`, yang menggambar ulang rute tersebut.

ErrorBoundary juga punya batas. Ia hanya menangkap error yang terjadi saat layar digambar (render). Ada dua jenis error yang tidak ia tangkap:

1. Request yang gagal. Error dari `useQuery` disimpan di properti `error`, dan kamu sudah menampilkannya sebagai pesan di layar.
2. Error di dalam event handler, yaitu fungsi yang jalan saat ada aksi, seperti `onPress`.

Untuk mengujinya, sisipkan sementara `throw new Error("uji boundary")` di awal `ProfileScreen`. Buka tab Profil dan lihat layar cadangannya. Setelah itu hapus baris tadi.

### Uji di HP sungguhan lewat Wi-Fi

**Emulator** adalah HP tiruan yang berjalan di laptop. Emulator tidak bisa meniru semuanya: jempol sungguhan, kamera, sinyal yang naik turun, dan rasa scroll di HP murah. Jadi ulangi skrip di atas di HP fisik dengan Expo Go. Caranya sama seperti di pelajaran [Menghubungkan Expo ke API](/belajar/fullstack/menghubungkan-expo-api). Berikut versi singkatnya.

HP perlu tahu **IP** laptop, yaitu alamat laptop di jaringan Wi-Fi. Bayangkan nomor rumah di satu kompleks perumahan. HP hanya bisa mengetuk pintu laptop kalau keduanya ada di kompleks yang sama (Wi-Fi yang sama) dan HP tahu nomor rumahnya.

Pertama, cari IP laptop:

<Tabs items={["Windows (PowerShell)", "macOS"]}>
<Tab>

# Sekali saja: izinkan port API di firewall (jalankan PowerShell sebagai Administrator)

```

</Tab>
<Tab>

```

</Tab>

Di Windows, `ipconfig` menampilkan alamat jaringan laptop. Perintah `New-NetFirewallRule` membuat aturan di **firewall** (penjaga di laptop yang memutuskan koneksi mana yang boleh masuk) supaya port 3000 boleh diakses. Aturan ini cukup dibuat sekali. Di macOS, `ipconfig getifaddr en0` langsung mencetak IP Wi-Fi.

Tulis IP itu di file `.env` milik `kuliah-app`, lalu jalankan ulang Metro dengan cache bersih. Variabel berawalan [`EXPO_PUBLIC_`](/glosarium#expo-public-env) dibaca saat **bundling**, yaitu saat Metro menyatukan semua kodemu menjadi satu paket untuk HP. Nilainya ikut tertulis di paket itu. Jadi perubahan `.env` baru terbaca setelah Metro dijalankan ulang.

```dotenv title=".env"
EXPO_PUBLIC_API_URL=http://192.168.1.10:3000
```

```bash
npx expo start -c
```

Sebelum mencurigai kode, buka `http://192.168.1.10:3000/api/health` di **browser HP**. Kalau muncul `{"status":"ok"}`, jaringannya sudah beres. Kalau halaman gagal dibuka, masalahnya ada di jaringan. Cek tiga hal ini:

1. HP dan laptop tersambung ke Wi-Fi yang sama.
2. Firewall laptop mengizinkan port 3000.
3. Wi-Fi kampus tidak memblokir koneksi antarperangkat. Pemblokiran ini disebut *client isolation*. Kalau ternyata diblokir, pakai hotspot HP sebagai gantinya.

Dari sisi server tidak ada yang perlu diubah. API pendamping sudah mendengarkan di `0.0.0.0`, artinya ia menerima koneksi dari perangkat lain di jaringan, bukan hanya dari laptop itu sendiri.

Pesan "Tidak bisa terhubung ke ... Cek IP, port, Wi-Fi, dan firewall." di aplikasi berarti `apiFetch` milikmu sudah bekerja dengan benar. Pesan itu memang dibuat untuk masalah jaringan seperti ini. Terakhir, IP laptop bisa berubah setiap kali pindah jaringan, misalnya dari Wi-Fi kos ke Wi-Fi kampus. Cek lagi `.env` setiap kali pindah tempat.

| Query key `["me"]` | `['auth', 'me']` | Semua key auth bisa di-invalidate bersama lewat awalan `['auth']` |
| `src/lib/theme.js` | `src/theme/` berisi token warna, jarak, dan ukuran huruf | Semua ukuran desain diatur di satu tempat |
| Import relatif `../../../` | **Alias** `@/` dari `tsconfig.json` (nama pendek untuk folder `src/`) | Import tidak rusak saat file dipindah |

Merapikan susunan kode tanpa mengubah perilakunya disebut **refactor**. Kerjakan satu baris tabel setiap kali. Misalnya, ganti `isLoggedIn` dan `isLoading` dengan satu `status`, lalu jalankan ulang skrip uji manual tadi. Kalau semua kriteria masih lolos, lanjut ke baris berikutnya. Pindah ke TypeScript, perintah `npm run typecheck` (pemeriksa tipe), dan tes otomatis dibahas lengkap di track Expert.

## Ide pengembangan

Kalau ingin terus mengasah aplikasimu, pilih satu atau dua ide berikut. Urutannya kira-kira dari yang paling ringan.

- **Pengingat tenggat.** Jadwalkan [notifikasi lokal](/glosarium#local-notification) (pengingat yang dijadwalkan oleh HP sendiri, tanpa server) pukul 19.00 sehari sebelum tenggat dengan `expo-notifications`. Batalkan jadwalnya saat tugas ditandai Selesai atau dihapus.
- **Catatan kuliah per pertemuan.** Ini bagian "Catatan" dari nama aplikasinya. Kamu perlu model `Note` baru di API (judul, isi, tanggal pertemuan, `courseId`), endpoint CRUD-nya, lalu satu layar di bawah detail mata kuliah. Latihan ini menyentuh semua lapisan, dari skema database sampai layar.
- **Tampilan kalender.** Kelompokkan tugas per tanggal tenggat dengan `SectionList` (daftar yang dibagi per bagian, masing-masing dengan judul), misalnya judul "Senin, 16 November" diikuti tugas-tugasnya.
- **Mode offline.** Simpan cache TanStack Query ke penyimpanan HP supaya daftar tetap terbaca tanpa internet. Konsepnya dibahas di [offline-first](/glosarium#offline-first).
- **Rilis ke HP teman.** Buat APK (file instalasi aplikasi Android) dengan [EAS](/glosarium#eas) Build, layanan Expo untuk membangun aplikasi. Bagikan tautannya ke teman sekelas. Mereka akan menekan tombol yang tidak pernah kamu coba dan menemukan masalah yang tidak terpikir olehmu.

Saat aplikasi makin besar, kamu akan butuh tipe data dan tes otomatis. Track **Expert** dimulai dari situ. [TypeScript end-to-end](/belajar/expert/typescript-end-to-end) menyatukan tipe data antara API dan aplikasi. [Testing mobile](/belajar/expert/testing-mobile) mengotomatiskan skrip uji yang tadi kamu jalankan dengan tangan. [Offline-first](/belajar/expert/offline-first) membahas ide mode offline di atas.

<Exercise title="Kode warna bebas" difficulty="sedang" hints={["Komponen `TextField` di `course-form.js` sudah bisa menampilkan pesan error di bawah kolomnya.", "Kolom teks dan swatch bisa membaca nilai yang sama, yaitu `values.color`.", "Tidak perlu menulis regex di aplikasi. Delapan swatch kadang kurang. Tambahkan kolom teks "Kode warna" di bawah swatch, supaya pengguna bisa mengetik warna sendiri seperti `#0EA5E9`. Kalau formatnya salah, pesan dari server harus muncul tepat di bawah kolom itu. Uji dengan `#12AB` (digitnya kurang) dan `12AB34` (tanpa `#`).

<Solution>

Ganti baris pesan error warna dengan `TextField`:

```diff title="src/components/course-form.js"
       </View>
-      {errors.color ? <Text style={styles.error}>{errors.color}</Text> : null}
+      <TextField
+        label="Kode warna"
+        value={values.color}
+        onChangeText={(text) => setField("color", text)}
+        error={errors.color}
+        placeholder="#4F46E5"
+        autoCapitalize="characters"
+        autoCorrect={false}
+        maxLength={7}
+      />
```

Cara kerjanya:

- Kolom ini dan swatch membaca nilai yang sama, `values.color`. Ketuk swatch, kolomnya ikut terisi. Ketik kode yang sama persis dengan salah satu palet, swatch itu ikut terpilih.
- `maxLength={7}` cukup untuk `#` ditambah enam digit. `autoCapitalize="characters"` membuat huruf otomatis besar, jadi cocok dengan penulisan palet.
- Simpan dengan `#12AB`. Server membalas 400 dengan `details` berisi `field: "color"` dan pesan "Warna harus berformat #RRGGBB, contoh #4F46E5". Fungsi `toCourseErrors` yang sudah ada menaruh pesan itu di `errors.color`, jadi pesannya muncul di bawah kolom tanpa kode tambahan.
- Kolom kosong juga ditolak server dengan pesan yang sama. Itu wajar, karena setiap mata kuliah memang perlu warna.

Kamu boleh menambah pemeriksaan format di aplikasi supaya pesan muncul tanpa menunggu server. Tapi server tetap pemeriksa terakhir. Request bisa datang dari mana saja, misalnya dari Postman atau aplikasi versi lama yang belum diperbarui. Pemeriksaan di aplikasi hanya mempercepat pesan, tidak menggantikan pemeriksaan di server.

</Solution>
</Exercise>

## Ringkasan

- Proyek besar dimulai dari spesifikasi: user story, kriteria penerimaan K1 sampai K8, dan milestone yang masing-masing ditutup dengan pengecekan.
- Navigasi memakai Stack di luar dan Tabs di dalam. Layar detail dan form tinggal di grup `(app)`, bukan di `(tabs)`, supaya terbuka tanpa tab bar.
- Mata kuliah punya hook sendiri, seperti `useCourses` dan `useDeleteCourse`. Setelah mata kuliah diubah atau dihapus, invalidate juga `taskKeys.all`, karena kartu tugas ikut menampilkan nama mata kuliah.
- Filter dikirim lewat query string. Pencarian di-debounce 400 ms, dan `keepPreviousData` menjaga daftar lama tetap tampil sampai daftar baru tiba.
- `getDeadlineBadge` adalah fungsi murni yang bisa diuji dengan `node`. Badge selalu berisi teks, karena warna saja tidak cukup.
- Logout menjalankan `signOut` dulu, baru `queryClient.clear()`, supaya data akun lama tidak terlihat oleh akun berikutnya.
- Empty state, skeleton, dan aksesibilitas membuat aplikasi enak dipakai. Uji 13 langkah di HP fisik membuktikan semuanya benar-benar jalan.
