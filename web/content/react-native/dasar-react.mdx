Pelajaran ini adalah pintu masuk Track 2. Komponen, JSX, dan props yang kamu pelajari di sini dipakai sama persis di React Native nanti. Bedanya hanya "batu bata"-nya: `<div>` di web, `<View>` di HP.

Prasyarat: kamu sudah nyaman dengan arrow function dan `map` dari [JavaScript Modern 1](/belajar/fondasi/javascript-modern-1), serta destructuring dan `import`/`export` dari [JavaScript Modern 2](/belajar/fondasi/javascript-modern-2). Semua contoh di track ini memakai React 19.

## Apa itu React?

<Callout type="analogi" title="Seperti menyusun balok LEGO">

Rumah LEGO tidak dicetak sekaligus. Rumah itu tersusun dari balok kecil: balok jendela, balok pintu, balok atap. Satu jenis balok bisa dipakai berkali-kali. Kalau jendelanya mau diganti, kamu cukup mencopot satu balok itu.

Di React, balok = **komponen**, rumah = satu layar aplikasi. Bedanya, balok LEGO selalu sama isinya. Komponen bisa menampilkan isi yang berbeda, tergantung data yang kamu berikan.

</Callout>

React adalah **library** JavaScript untuk membangun UI. Library artinya kumpulan kode siap pakai buatan orang lain yang kamu panggil dari kodemu. UI (*user interface*) adalah semua yang dilihat dan disentuh pengguna: teks, tombol, kotak isian.

UI di React disusun dari **komponen** (*component*). Komponen adalah potongan UI yang berdiri sendiri, misalnya satu kartu tugas. Komponen ditulis sebagai fungsi JavaScript biasa. Fungsi itu menerima data, lalu mengembalikan gambaran tampilannya.

Kata kunci berikutnya adalah **deklaratif**.

<Callout type="analogi" title="Memesan nasi goreng di warung">

Cara imperatif itu seperti masuk ke dapur warung dan mengajari koki: "nyalakan kompor, tuang minyak, masukkan nasi". Cara deklaratif itu seperti bilang ke penjual: "nasi goreng pedas, tanpa telur". Kamu cukup menyebut hasil akhirnya. Koki (React) yang memasak.

</Callout>

- **Imperatif** berarti memberi instruksi langkah demi langkah. Di kode kiri, kamu sendiri yang membuat elemen, mengisi teks, dan menempelkannya ke halaman. Kalau judul berubah, kamu juga yang harus mencari dan mengubahnya.
- **Deklaratif** berarti menjelaskan hasil akhirnya. Di kode kanan, kamu hanya menulis bentuk kartunya. Saat data berubah, React membandingkan tampilan lama dan baru. Lalu React mengubah bagian yang berbeda saja di **DOM** (susunan elemen halaman yang sedang tampil di browser).

1. Komponen adalah fungsi yang mengembalikan JSX. Kalau tidak ingin menampilkan apa pun, komponen boleh mengembalikan `null`.
2. Nama komponen wajib diawali huruf kapital: `TaskCard`, bukan `taskCard`. React melihat huruf pertama untuk membedakan komponen buatanmu dari tag HTML bawaan seperti `div` atau `p`.

## Aturan JSX

<Callout type="analogi" title="Seperti mengisi formulir KRS">

Formulir KRS punya aturan tulis. NIM harus di kotak NIM. Tanda tangan harus di kolom tanda tangan. Kalau aturannya dilanggar, petugas akademik menolak formulirmu, walaupun isinya benar.

JSX juga punya aturan tulis. Petugas yang memeriksanya adalah alat bernama Babel. Kalau aturannya dilanggar, Babel menolak dan menampilkan pesan error.

</Callout>

JSX (*JavaScript XML*) adalah cara menulis tampilan yang mirip HTML, tetapi di dalam file JavaScript. Browser sebenarnya tidak mengerti JSX. Ada alat bernama **Babel** (penerjemah kode) yang mengubah JSX menjadi panggilan fungsi biasa, kira-kira `jsx("h1", { children: "Halo" })`. Karena ujung-ujungnya JSX adalah JavaScript, aturannya sedikit lebih ketat daripada HTML:

| Aturan | Salah | Benar |
| --- | --- | --- |
| Satu elemen akar per `return` | `<h1>A</h1><p>B</p>` | `<><h1>A</h1><p>B</p></>` |
| Pakai `className`, bukan `class` | `<div class="card">` | `<div className="card">` |
| Semua tag wajib ditutup | `<img src={url}>` | `<img src={url} />` |
| Nilai JavaScript ditulis di kurung kurawal | `<h3>task.title</h3>` | `<h3>{task.title}</h3>` |
| Nama atribut memakai camelCase | `onclick`, `tabindex` | `onClick`, `tabIndex` |
| `style` berupa object | `style="color: red"` | `style={{ color: "red" }}` |

*camelCase* artinya kata pertama huruf kecil, lalu tiap kata berikutnya diawali huruf kapital, seperti `onClick`. Dua bagian berikut membahas aturan yang paling sering bikin bingung.

### Satu akar atau Fragment

Sebuah fungsi hanya bisa mengembalikan satu nilai. Kalau kamu menulis dua elemen bersebelahan di `return`, itu sama saja mencoba mengembalikan dua nilai. Babel akan menolak dengan pesan `Adjacent JSX elements must be wrapped in an enclosing tag. Did you want a JSX fragment <>...</>?`. Artinya: "elemen yang bersebelahan harus dibungkus satu tag".

Mirip kurir ojek online yang hanya mau membawa satu paket. Kalau kamu punya dua barang, masukkan dulu ke satu kantong. Solusinya di JSX sama: bungkus dengan satu elemen induk. Kalau kamu tidak ingin menambah `<div>` ekstra ke halaman, pakai **Fragment** `<>...</>`. Fragment adalah pembungkus "kosong" yang tidak ikut muncul di DOM, seperti kantong bening yang dibuang begitu paket sampai.

```jsx
function TaskHeader() {
  return (
    <>
      <h2>Tugas Minggu Ini</h2>
      <p>Prioritaskan yang deadline-nya paling dekat.</p>
    </>
  );
}
```

Komponen ini mengembalikan satu judul dan satu paragraf. Keduanya dibungkus `<>` dan `</>`, jadi dihitung sebagai satu nilai. Di halaman, yang muncul hanya `h2` dan `p`.

Perhatikan juga tanda kurung `(` setelah `return`. Kalau JSX baru dimulai di baris berikutnya tanpa `(`, JavaScript otomatis menyisipkan titik koma setelah `return`. Akibatnya fungsi mengembalikan `undefined`, dan tidak ada yang tampil.

### Kurung kurawal: jendela ke JavaScript

<Callout type="analogi" title="Seperti template surat undangan">

Panitia acara kampus punya template undangan: "Kepada Yth. ____, kami mengundang Anda ke acara ____". Sebagian besar teksnya tetap. Bagian kosong diisi nama dan acara yang berbeda untuk tiap orang.

JSX mirip template itu. Bagian yang mirip HTML = teks tetap. Kurung kurawal = bagian kosong yang diisi nilai dari JavaScript.

</Callout>

Di dalam JSX, `{ }` adalah "jendela" untuk menyisipkan **ekspresi** JavaScript. Ekspresi adalah kode yang menghasilkan nilai: variabel, operasi `a + b`, pemanggilan fungsi, ternary, sampai `map`. **Pernyataan** (*statement*) seperti `if` atau `for` tidak menghasilkan nilai. Karena itu `if` dan `for` tidak bisa ditaruh langsung di dalam kurung kurawal.

```jsx
const course = { name: "Basis Data", lecturer: "Bu Rina", sks: 3 };

function CourseInfo() {
  return (
    <div className="course" title={"Info " + course.name}>
      <h3>{course.name.toUpperCase()}</h3>
      <p>Dosen: {course.lecturer}</p>
      <p>Tatap muka: {course.sks * 50} menit per minggu</p>
    </div>
  );
}
```

```txt
BASIS DATA
Dosen: Bu Rina
Tatap muka: 150 menit per minggu
```

Cara membaca kode di atas:

- `course` adalah object biasa berisi nama, dosen, dan jumlah SKS.
- `{course.name.toUpperCase()}` memanggil fungsi, jadi judulnya tampil huruf besar semua.
- `{course.sks * 50}` menghitung dulu, lalu hasilnya (150) yang tampil.
- Atribut `title` diisi gabungan string `"Info " + course.name`.

Atribut bisa diisi string biasa (`"..."`) atau ekspresi (`{...}`). Pada `style={{ color: "red" }}` ada dua pasang kurung kurawal. Pasangan luar berarti "ini ekspresi JavaScript". Pasangan dalam adalah object-nya.

## Props: mengirim data ke komponen

<Callout type="analogi" title="Seperti pesanan ke tukang jahit">

Tukang jahit punya satu pola kemeja. Tiap pelanggan datang membawa catatan pesanan: ukuran M, warna biru, lengan panjang. Polanya sama, hasilnya beda-beda sesuai catatan.

Pola kemeja = komponen `TaskCard`. Catatan pesanan = **props**. Pelanggan = komponen induk yang memakai `TaskCard`. Tukang jahit tidak boleh mengubah isi catatan pesanan seenaknya. Begitu juga komponen tidak boleh mengubah props yang diterimanya.

</Callout>

Komponen yang selalu menampilkan teks yang sama tidak terlalu berguna. Kita ingin satu `TaskCard` bisa menampilkan tugas apa saja. Caranya lewat **props** (*properties*). Props adalah data yang dikirim dari komponen induk (yang memakai) ke komponen anak (yang dipakai). Cara menulisnya seperti atribut HTML.

React mengumpulkan semua atribut itu menjadi satu object. Object itu dikirim sebagai parameter pertama fungsi komponen. Biasanya kita langsung membongkarnya dengan destructuring, lengkap dengan nilai default (nilai cadangan kalau prop tidak dikirim):

```jsx
function TaskCard({ title, course, priority = "sedang", done }) {
  return (
    <div className="card">
      <h3>{title}</h3>
      <p>
        {course} · prioritas {priority}
      </p>
      <p>{done ? "Selesai" : "Belum selesai"}</p>
    </div>
  );
}

// Dipakai oleh komponen induk:
<TaskCard title="Kuis SQL" course="Basis Data" priority="tinggi" done={false} />;
<TaskCard title="Setup Expo" course="Pemrograman Mobile" done={true} />;
// Kartu kedua memakai priority default: "sedang"
```

Yang terjadi di kode ini: kartu pertama menerima empat props. Kartu kedua tidak mengirim `priority`, jadi nilai default `"sedang"` yang dipakai.

Empat hal yang perlu kamu tahu tentang props:

- **String** boleh ditulis dengan tanda kutip. Nilai lain (angka, boolean, array, object, fungsi) wajib memakai kurung kurawal: `sks={3}`, `done={false}`.
- Hati-hati dengan `done="false"`. Itu string yang tidak kosong. JavaScript menganggapnya *truthy*, yaitu dihitung "benar" saat dipakai sebagai kondisi. Akibatnya tugasmu malah tampil "Selesai".
- Props bersifat **read-only** (hanya boleh dibaca). Komponen tidak boleh mengubah props yang diterimanya. Dengan props yang sama, komponen harus selalu menghasilkan tampilan yang sama. Komponen seperti ini disebut *pure* (murni).
- Kalau kamu punya object `task`, tulis `<TaskCard {...task} />` untuk mengirim semua propertinya sekaligus sebagai props. Ini memakai spread yang sudah kamu kenal.

Bingkai = komponen `Card`. Foto yang kamu selipkan = `children`.

</Callout>

Apa pun yang kamu letakkan di antara tag pembuka dan tag penutup sebuah komponen akan diterima sebagai prop khusus bernama `children`. Dengan `children`, kamu bisa membuat komponen "pembungkus". Contohnya `Card` yang hanya mengurus bingkai, sementara isinya bebas.

## Render kondisional

<Callout type="analogi" title="Seperti papan menu warung">

Kalau stok ayam habis, penjual menempel tulisan "Habis" di samping menu ayam. Kalau masih ada, tulisan itu tidak dipasang. Tampilan papan menu mengikuti keadaan dapur.

Keadaan dapur = data (props). Tulisan "Habis" = bagian JSX yang muncul hanya kalau syaratnya terpenuhi.

</Callout>

Sering kali tampilan bergantung pada data. Tugas yang terlambat diberi peringatan. Tugas tanpa deadline tidak menampilkan tanggal. Menampilkan sesuatu hanya kalau syaratnya terpenuhi disebut **render kondisional**. *Render* artinya menggambar tampilan ke layar. Karena JSX adalah JavaScript, kamu memakai alat JavaScript biasa:

- **`if` + `return` lebih awal** di luar JSX. Cocok kalau tampilannya sangat berbeda.
- **Ternary** `kondisi ? A : B` di dalam JSX. Dipakai untuk memilih salah satu dari dua tampilan.
- **`&&`** untuk "tampilkan ini, atau tidak sama sekali".
- **`return null`** agar komponen tidak menampilkan apa pun.

```jsx
function DeadlineInfo({ daysLeft }) {
  if (daysLeft === undefined) return null;

  return (
    <p>
      {daysLeft < 0 ? "Terlambat!" : "Sisa " + daysLeft + " hari"}
      {daysLeft <= 1 && <strong> Segera kerjakan</strong>}
    </p>
  );
}
```

```txt
<DeadlineInfo />               → (tidak tampil apa-apa)
<DeadlineInfo daysLeft={5} />  → Sisa 5 hari
<DeadlineInfo daysLeft={1} />  → Sisa 1 hari Segera kerjakan
<DeadlineInfo daysLeft={-2} /> → Terlambat! Segera kerjakan
```

Cara membaca `DeadlineInfo`:

- Baris pertama di dalam fungsi: kalau `daysLeft` tidak dikirim, komponen langsung mengembalikan `null`. Tidak ada yang tampil.
- Ternary memilih teks "Terlambat!" kalau `daysLeft` negatif. Kalau tidak, tampil "Sisa ... hari".
- `daysLeft <= 1 && ...` menambahkan teks tebal "Segera kerjakan" hanya kalau sisa harinya 1 atau kurang.

Jebakan klasik ada pada `&&` dengan angka. `{tasks.length && <p>Ada tugas</p>}` akan menampilkan angka **0** di layar saat array kosong. Penyebabnya, `0 && ...` menghasilkan `0`, dan React tetap menampilkan angka. Nilai `false`, `null`, dan `undefined` tidak ditampilkan, tetapi angka 0 ditampilkan. Jadi ubah dulu menjadi boolean: `tasks.length > 0 && ...`.

## Sekilas: list dengan `key`

<Callout type="analogi" title="Seperti NIM di daftar hadir">

Dosen mengecek daftar hadir pakai NIM, bukan nomor urut baris. Kalau ada mahasiswa yang pindah kelas, nomor urut semua orang di bawahnya bergeser. NIM tiap orang tetap sama.

NIM = `key`. Nomor urut baris = indeks array. Itulah sebabnya `key` sebaiknya diambil dari `id` data, bukan dari urutan.

</Callout>

Data dari API hampir selalu berupa array. Untuk menampilkannya, ubah array data menjadi array JSX dengan `map`. Setiap elemen hasil `map` wajib diberi prop **`key`**. Isinya string atau angka yang unik di antara saudaranya, biasanya `id` dari database. React memakai `key` untuk mengenali item mana yang mana saat list berubah, misalnya ada yang ditambah, dihapus, atau diurutkan ulang.

Kalau `key` lupa diberikan, React menampilkan peringatan di console (panel pesan untuk programmer di browser): `Each child in a list should have a unique "key" prop.` Satu catatan lagi: `key` dibaca oleh React sendiri dan tidak diteruskan sebagai props. Jadi di dalam `TaskItem` kamu tidak bisa membaca `props.key`. Kenapa indeks array adalah `key` yang buruk akan dibahas di [useEffect, List & Custom Hook](/belajar/react-native/effect-list-custom-hook).

<ReactPlayground title="List, key & kondisional" height={380} code={`
const tasks = [
  { id: 1, title: "Laporan Praktikum Basis Data", course: "Basis Data", done: false },
  { id: 2, title: "Kuis Expo Router", course: "Pemrograman Mobile", done: true },
  { id: 3, title: "Rangkum Bab Normalisasi", course: "Basis Data", done: false },
];

function TaskItem({ title, course, done }) {
  return (
    <li style={{ marginBottom: 8 }}>
      <span style={{ textDecoration: done ? "line-through" : "none" }}>{title}</span>{" "}
      <small>({course})</small>
      {done && <strong> ✓ selesai</strong>}
    </li>
  );
}

export default function App() {
  const pending = tasks.filter((t) => !t.done);

  return (
    <main style={{ fontFamily: "system-ui", padding: 16 }}>
      <h1>Tugas Sari</h1>
      {pending.length > 0 ? (
        <p>{pending.length} tugas belum selesai.</p>
      ) : (
        <p>Semua tugas beres!</p>
      )}
      <ul>
        {tasks.map((task) => (
          <TaskItem key={task.id} title={task.title} course={task.course} done={task.done} />
        ))}
      </ul>
    </main>
  );
}
`} />

Di kode ini, `pending` berisi tugas yang belum selesai. Ternary memilih kalimat "X tugas belum selesai" atau "Semua tugas beres!". Lalu `tasks.map(...)` mengubah tiap object tugas menjadi satu `<TaskItem>`, masing-masing dengan `key={task.id}`.

Coba ubah semua `done` menjadi `true`, lalu lihat pesannya berganti. Setelah itu hapus `key={task.id}` dan buka console di DevTools browser (<Kbd>F12</Kbd>) untuk melihat peringatannya.

## Berpikir dalam komponen: membedah TaskCard

<Callout type="analogi" title="Seperti membagi laporan kelompok">

Sebelum menulis laporan kelompok, kalian membagi laporan menjadi bab. Tiap bab punya satu topik. Kalian menyusun daftar isi, lalu tiap orang mengerjakan babnya di file sendiri. Terakhir semua bab digabung.

Laporan = satu layar. Bab = komponen. Daftar isi = hierarki komponen. File per bab = file per komponen. Bedanya, satu komponen bisa dipakai berulang kali di layar yang sama. Bab laporan tidak ditulis dua kali.

</Callout>

Dokumentasi resmi React punya panduan terkenal, [Thinking in React](https://react.dev/learn/thinking-in-react). Isinya: sebelum menulis kode, pecah dulu tampilan menjadi komponen. Kita praktikkan langsung pada layar daftar tugas aplikasi capstone. Gambar di bawah adalah *mockup*, yaitu sketsa kasar tampilan sebelum dibuat.

</Step>

## Kesalahan umum

<Callout type="warning" title="Pesan error yang paling sering muncul">

- **`Adjacent JSX elements must be wrapped in an enclosing tag`**: ada dua elemen bersebelahan di `return`. Bungkus dengan `<div>` atau Fragment `<>...</>`.
- **`Unterminated JSX contents`**: biasanya ada tag yang tidak ditutup, misalnya `<img>` atau `<input>`. Di JSX, tulis `<img />`.
- **``Invalid DOM property `class`. Did you mean `className`?``**: kamu menyalin HTML mentah. Ganti `class` dengan `className`, dan `for` dengan `htmlFor`.
- **`The tag <taskCard> is unrecognized in this browser`**: nama komponen diawali huruf kecil, jadi React mengira itu tag HTML. Ganti menjadi `TaskCard`.
- **`Objects are not valid as a React child (found: object with keys {id, title})`**: kamu menaruh object utuh di JSX, misalnya `{task}`. React tidak tahu cara menampilkan object. Tampilkan propertinya saja, misalnya `{task.title}`.
- **Angka 0 muncul sendirian di layar**: ini pola `{list.length && ...}`. Ganti menjadi `{list.length > 0 && ...}`.
- **Tidak ada yang tampil sama sekali**: cek apakah `return` diikuti `(` di baris yang sama. Cek juga apakah komponen akar sudah di-`export default`.

</Callout>

```jsx
const courses = [
  { id: 1, name: "Basis Data", lecturer: "Bu Rina", sks: 3 },
  { id: 2, name: "Pemrograman Mobile", lecturer: "Pak Dimas", sks: 4 },
  { id: 3, name: "Etika Profesi", lecturer: "Bu Wulan" },
];

function CourseCard({ name, lecturer, sks }) {
  return (
    <article style={{ border: "1px solid #ddd", borderRadius: 8, padding: 12, marginBottom: 8 }}>
      <h3 style={{ margin: 0 }}>{name}</h3>
      <p style={{ margin: "4px 0" }}>Dosen: {lecturer}</p>
      <small>{sks ? sks + " SKS" : "SKS belum diisi"}</small>
    </article>
  );
}

export default function App() {
  return (
    <main style={{ fontFamily: "system-ui", padding: 16 }}>
      <h1>Mata Kuliah Semester Ini</h1>
      {courses.map((course) => (
        <CourseCard key={course.id} name={course.name} lecturer={course.lecturer} sks={course.sks} />

    </main>
  );
}
```

</Solution>

<Exercise title="Komponen Section dengan children" difficulty="sedang" hints={["Prop `children` berisi apa pun di antara tag pembuka dan penutup.", "Hitung jumlah item dengan `tasks.length`, lalu bandingkan dengan `> 0`."]}>

Buat komponen `Section` yang menerima `title` dan `children`, lalu menampilkan judul `h2` di atas isinya. Pakai `Section` dua kali di `App`: "Belum selesai" dan "Selesai", masing-masing berisi `<ul>` tugas yang sesuai dari array `tasks` di playground "List, key & kondisional". Jika sebuah bagian kosong, tampilkan teks "Tidak ada tugas" alih-alih `<ul>` kosong.

<Solution>

```jsx
const tasks = [
  { id: 1, title: "Laporan Praktikum Basis Data", done: false },
  { id: 2, title: "Kuis Expo Router", done: true },
  { id: 3, title: "Rangkum Bab Normalisasi", done: false },
];

function Section({ title, children }) {
  return (
    <section>
      <h2>{title}</h2>
      {children}
    </section>
  );
}

function TaskList({ items }) {
  if (items.length === 0) return <p>Tidak ada tugas</p>;
  return (
    <ul>
      {items.map((task) => (
        <li key={task.id}>{task.title}</li>
      ))}
    </ul>
  );
}

export default function App() {
  return (
    <main style={{ fontFamily: "system-ui", padding: 16 }}>
      <Section title="Belum selesai">
        <TaskList items={tasks.filter((t) => !t.done)} />
      </Section>
      <Section title="Selesai">
        <TaskList items={tasks.filter((t) => t.done)} />
      </Section>
    </main>
  );
}
```

`Section` tidak tahu apa isinya. Inilah yang disebut komposisi. Logika "kosong atau tidak" dipisah ke `TaskList` dengan `return` lebih awal, sehingga JSX di `App` tetap bersih.

</Solution>
</Exercise>

## Ringkasan

- React membangun UI secara **deklaratif**: kamu menjelaskan tampilan untuk data tertentu, React yang memperbarui DOM.
- Komponen adalah fungsi bernama **PascalCase** yang mengembalikan JSX (atau `null`).
- Aturan JSX: satu akar (atau Fragment `<>...</>`), `className`, semua tag ditutup, ekspresi di dalam `{ }`, atribut camelCase.
- **Props** mengalirkan data dari induk ke anak, bersifat read-only. Nilai non-string ditulis dengan `{ }`.
- **`children`** memungkinkan komposisi: komponen pembungkus yang tidak peduli isinya.
- Render kondisional memakai `if`/`return` lebih awal, ternary, `&&` (hati-hati angka 0), dan `return null`.
- List dirender dengan `map`, dan tiap item butuh `key` unik yang stabil, idealnya `id`.
