## Pengantar

Buka modal "Tugas Baru" yang kamu buat di [Expo Router](/belajar/react-native/expo-router). **Modal** adalah layar yang muncul menutupi layar sebelumnya, mirip jendela pop-up. Sekarang ketuk kolom judul. Keyboard naik dan menutupi separuh layar. Kalau form-nya lebih panjang, tombol Simpan ikut tertutup. Ketukan pertama di tombol itu pun hanya menutup keyboard, belum menyimpan. Masalah kecil seperti ini membuat aplikasi terasa belum jadi.

Di pelajaran ini, modal tersebut kita ubah menjadi form tugas lengkap. Isinya judul, mata kuliah, deadline, deskripsi, prioritas, dan status selesai. Kamu akan belajar tiga hal:

- membuat form **terkontrol**: semua isi form disimpan di satu objek state, dan pesan error muncul tepat di bawah kolom yang salah;
- memunculkan jenis keyboard yang cocok untuk tiap kolom, lalu memindahkan kursor ke kolom berikutnya dengan tombol "Next";
- menjaga agar keyboard tidak menutupi kolom yang sedang diisi, dengan `KeyboardAvoidingView` atau library `react-native-keyboard-controller`.

Kita masih memakai project `latihan-rn`. Tombol Simpan belum menyimpan ke mana pun. Datanya hanya dicetak ke terminal, lalu modal ditutup. Penyimpanan sungguhan dibahas di [State Global & Storage](/belajar/react-native/state-global-storage).

## Form terkontrol di React Native

<Callout type="analogi" title="Seperti mendikte formulir ke petugas teller">

Di bank, kamu menyebut nama dan nomor rekening, lalu petugas teller menuliskannya di formulir. Yang tertulis di formulir hanyalah apa yang dicatat petugas. Kalau petugas lupa mencatat, kolomnya tetap kosong walaupun kamu sudah bicara.

Di form terkontrol: kamu mengetik = kamu menyebut data. `onChangeText` = telinga petugas. State = formulir di meja petugas. `value` = tulisan yang terbaca di formulir itu. Bedanya, "petugas" di aplikasi mencatat secepat kamu mengetik, jadi kamu tidak merasakan jeda.

</Callout>

Kamu sudah mengenal [controlled input](/glosarium#controlled-input) di [State & Event](/belajar/react-native/state-event). Artinya, nilai input disimpan di state, dan setiap ketikan memperbarui state itu. Layar lalu menampilkan isi state. Di React Native polanya sama, hanya nama prop-nya yang berbeda. `TextInput` (komponen kolom isian teks) menerima dua prop penting:

- `value`: teks yang ditampilkan, diambil dari state;
- `onChangeText`: fungsi yang dipanggil setiap kali teks berubah.

Argumen `onChangeText` langsung berupa **string** (teks biasa). Di web kamu harus membaca `e.target.value` dari objek event. Di React Native langkah itu tidak ada.

Form tugas punya enam kolom. Kamu bisa saja membuat enam `useState`, tetapi itu merepotkan. Lebih rapi kalau semuanya disimpan dalam satu objek, lalu diubah lewat satu fungsi:

```jsx
const [form, setForm] = useState({
  title: '',
  course: '',
  deadline: '',
  description: '',
  priority: 'sedang',
  done: false,
});

function setField(name, value) {
  setForm((prev) => ({ ...prev, [name]: value }));
}

// di JSX
<TextInput value={form.title} onChangeText={(text) => setField('title', text)} />
```

Cara membaca kode di atas:

- `form` adalah satu objek berisi enam kolom. Nilai awalnya kosong, kecuali prioritas `'sedang'` dan `done` bernilai `false`.
- `setField('title', 'Rangkum bab 3')` hanya mengganti kolom `title`. Kolom lain tidak berubah.
- `prev => ...` artinya "ambil isi form yang paling baru dulu". Ini mencegah dua ketikan cepat saling menimpa.
- `...prev` (**spread**) menyalin semua kolom lama. Setelah itu `[name]: value` menimpa satu kolom saja. Tanda kurung siku berarti nama kolomnya diambil dari isi variabel `name`.

Setiap kolom sebaiknya memunculkan keyboard yang cocok dengan isinya. Kolom email butuh tombol `@`, kolom angka cukup menampilkan angka. Berikut prop `TextInput` yang paling sering dipakai di form:

| Prop | Contoh nilai | Gunanya |
| --- | --- | --- |
| `keyboardType` | `email-address`, `numeric`, `number-pad`, `phone-pad` | Jenis keyboard yang muncul |
| `returnKeyType` | `next`, `done`, `go`, `send`, `search` | Label tombol Enter di keyboard |
| `autoCapitalize` | `none`, `sentences`, `words`, `characters` | Huruf besar otomatis |
| `autoCorrect` | `false` | Mematikan koreksi otomatis (untuk email, kode) |
| `autoComplete` | `email`, `current-password`, `name`, `off` | Memberi tahu HP jenis isiannya, supaya bisa diisi otomatis |
| `secureTextEntry` | `true` | Menyembunyikan teks (untuk password) |
| `multiline` | `true` | Teks banyak baris, Enter menambah baris |
| `maxLength` | `200` | Batas jumlah karakter |

## Merancang form tugas

Berikut file yang kita sentuh di `latihan-rn`. File bertanda bintang adalah file baru atau file yang diubah. Aturan validasi ditaruh di file sendiri, supaya bisa diuji tanpa membuka aplikasi.

Rancangan kolomnya:

- **Judul** wajib, 3–200 karakter. Huruf pertama otomatis kapital (`autoCapitalize="sentences"`).
- **Mata kuliah** opsional. Setiap kata dikapitalkan (`autoCapitalize="words"`). Koreksi otomatis dimatikan, karena nama mata kuliah sering berupa singkatan.
- **Deadline** opsional, ditulis sebagai teks `YYYY-MM-DD`. Formatnya sama dengan yang dipakai API (server penyimpan data) di Track 3.
- **Deskripsi** opsional, `multiline`, maksimal 2000 karakter.
- **Prioritas** dipilih dari tiga tombol berjajar (rendah, sedang, tinggi).
- **Selesai** memakai `Switch`.

<Callout type="analogi" title="Seperti memesan es teh di kedai">

Penjual tidak memintamu menulis ukuran gelas. Ia menunjuk tiga pilihan di menu: kecil, sedang, besar. Kamu cukup menunjuk satu. Untuk "pakai gula atau tidak", jawabannya hanya ya atau tidak, mirip saklar lampu.

Prioritas = pilihan ukuran gelas, jadi cukup tiga tombol. Status selesai = saklar lampu, jadi pakai `Switch`. Bedanya, penjual bisa mengangguk saat kamu menunjuk. Di aplikasi, tombol yang terpilih harus kamu tandai sendiri dengan warna.

</Callout>

Untuk prioritas, kita pakai tiga [Pressable](/glosarium#pressable) (komponen yang bisa diketuk) yang disusun seperti *segmented control*, yaitu deretan tombol yang hanya boleh dipilih satu:

```jsx
// PRIORITIES = ['rendah', 'sedang', 'tinggi'], diekspor dari src/lib/validate-task.js
const PRIORITY_LABEL = { rendah: 'Rendah', sedang: 'Sedang', tinggi: 'Tinggi' };

<View style={styles.segment} accessibilityRole="radiogroup">
  {PRIORITIES.map((p) => {
    const selected = form.priority === p;
    return (
      <Pressable
        key={p}
        onPress={() => setField('priority', p)}
        accessibilityRole="radio"
        accessibilityState={{ checked: selected }}
        style={[styles.segmentItem, selected && styles.segmentItemActive]}
      >
        <Text style={[styles.segmentText, selected && styles.segmentTextActive]}>
          {PRIORITY_LABEL[p]}
        </Text>
      </Pressable>
    );
  })}
</View>
```

`PRIORITIES.map` membuat satu tombol untuk tiap prioritas. Tombol yang sedang dipilih (`selected`) diberi gaya berwarna. `accessibilityRole` dan `accessibilityState` memberi tahu pembaca layar bahwa ini pilihan radio dan mana yang sedang aktif. Bagian aksesibilitas di bawah membahasnya lebih lanjut.

`Switch` adalah tombol geser on/off. Cara kerjanya sama seperti input terkontrol, hanya nilainya **boolean** (`true` atau `false`). `value` dipakai untuk membaca, `onValueChange` untuk mengubah.

```jsx
<View style={styles.switchRow}>
  <Text style={styles.label}>Sudah selesai</Text>
  <Switch
    value={form.done}
    onValueChange={(value) => setField('done', value)}
    trackColor={{ true: '#4f46e5' }}
    accessibilityLabel="Tandai tugas sudah selesai"
  />
</View>
```

## Validasi dan pesan error

<Callout type="analogi" title="Seperti petugas akademik memeriksa formulir">

Saat daftar ulang, petugas akademik memeriksa formulirmu. NIM harus terisi, tanggal lahir harus tanggal yang benar. Kolom yang salah diberi catatan kecil di sebelahnya. Petugas yang baik tidak menegur kolom yang belum sempat kamu isi. Ia baru menegur setelah kamu selesai dengan kolom itu.

Petugas = fungsi `validateTask`. Catatan kecil = objek error. "Selesai dengan kolom itu" = kolom sudah ditinggalkan dan tercatat di `touched`. Bedanya, petugas di aplikasi memeriksa ulang seluruh formulir setiap kali kamu mengetik satu huruf.

</Callout>

[Validasi](/glosarium#validation) ditulis sebagai **fungsi murni**. Artinya, fungsi ini hanya membaca masukan lalu mengembalikan hasil, tanpa mengubah apa pun di luar dirinya. Masukan yang sama selalu memberi hasil yang sama, seperti kalkulator. Masukannya isi form, keluarannya objek error. Kolom yang lolos tidak masuk ke objek itu. Jadi, form dianggap valid kalau objek error kosong.

```js title="src/lib/validate-task.js"
export const PRIORITIES = ['rendah', 'sedang', 'tinggi'];

export function isRealDate(text) {
  const [y, m, d] = text.split('-').map(Number);
  const date = new Date(Date.UTC(y, m - 1, d));
  return (
    date.getUTCFullYear() === y &&
    date.getUTCMonth() === m - 1 &&
    date.getUTCDate() === d
  );
}

export function validateTask(values) {
  const errors = {};
  const title = values.title.trim();

  if (!title) errors.title = 'Judul wajib diisi';
  else if (title.length < 3) errors.title = 'Judul minimal 3 karakter';
  else if (title.length > 200) errors.title = 'Judul maksimal 200 karakter';

  if (values.course.length > 100) errors.course = 'Mata kuliah maksimal 100 karakter';

  if (values.deadline) {
    if (!/^[0-9]{4}-[0-9]{2}-[0-9]{2}$/.test(values.deadline)) {
      errors.deadline = 'Format tanggal: YYYY-MM-DD';
    } else if (!isRealDate(values.deadline)) {
      errors.deadline = 'Tanggal itu tidak ada di kalender';
    }
  }

  if (values.description.length > 2000) {
    errors.description = 'Deskripsi maksimal 2000 karakter';
  }

  if (!PRIORITIES.includes(values.priority)) errors.priority = 'Pilih prioritas';

  return errors;
}
```

Cara membaca `validateTask`:

- `trim()` membuang spasi di awal dan akhir judul. Judul yang isinya spasi saja dianggap kosong.
- Judul dicek berurutan: kosong, kurang dari 3 karakter, lebih dari 200 karakter. Hanya pesan pertama yang cocok yang disimpan.
- Deadline hanya dicek kalau diisi, karena kolom ini opsional.
- Prioritas harus salah satu isi `PRIORITIES`.

Deadline diperiksa dua kali. Pertama, **regex** (pola pencocok teks) hanya mengecek bentuk `0000-00-00`. Kedua, `isRealDate` mengecek apakah tanggal itu benar-benar ada di kalender. `Date` di JavaScript diam-diam "membetulkan" tanggal yang tidak ada: 31 Februari diubah menjadi 3 Maret. Jadi, kalau tahun, bulan, atau tanggal hasilnya berbeda dari yang diketik, tanggal itu palsu. Coba panggil fungsinya dengan dua contoh:

```js
validateTask({ title: '  ', course: '', deadline: '2026-02-31', description: '', priority: 'sedang' });
validateTask({ title: 'Rangkum bab 3', course: 'Basis Data', deadline: '2026-07-15', description: '', priority: 'tinggi' });
```

```txt
{
  title: 'Judul wajib diisi',
  deadline: 'Tanggal itu tidak ada di kalender'
}
{}
```

Contoh pertama gagal di dua kolom. Contoh kedua lolos semua, jadi hasilnya objek kosong `{}`.

Lalu, kapan pesan error ditampilkan? Kalau langsung muncul saat layar dibuka, pengguna sudah ditegur sebelum sempat mengetik. Caranya: catat kolom yang sudah pernah ditinggalkan di state `touched`. Kolom dianggap ditinggalkan saat `onBlur` terpanggil (**blur** = kursor keluar dari kolom itu). Error hanya ditampilkan untuk kolom yang sudah tercatat.

```jsx
const [touched, setTouched] = useState({});
const errors = validateTask(form);
const isValid = Object.keys(errors).length === 0;

function touch(name) {
  setTouched((prev) => ({ ...prev, [name]: true }));
}

function FieldError({ message }) {
  if (!message) return null;
  return (
    <Text style={styles.error} accessibilityLiveRegion="polite">
      {message}
    </Text>
  );
}

// di JSX, tepat di bawah TextInput judul
<FieldError message={touched.title ? errors.title : undefined} />
```

Isi kode ini:

- `touched` mulai dari objek kosong. Setelah kolom judul ditinggalkan, `touch('title')` membuatnya berisi `{ title: true }`.
- `isValid` bernilai `true` kalau objek `errors` tidak punya satu kunci pun.
- `FieldError` adalah komponen kecil untuk menampilkan pesan merah. Kalau tidak ada pesan, ia tidak menampilkan apa-apa (`return null`).
- `touched.title ? errors.title : undefined` artinya: tampilkan error judul hanya kalau judul sudah pernah ditinggalkan.

`errors` dihitung ulang setiap **render** (setiap kali layar digambar ulang), bukan disimpan di state. Nilainya selalu bisa dihitung dari `form`. Kalau disimpan terpisah, suatu saat keduanya bisa tidak cocok. Misalnya, judul sudah benar tetapi pesan error lama masih tampil.

Tombol Simpan dinonaktifkan selama form belum valid:

```jsx
<Pressable
  onPress={simpan}
  disabled={!isValid}
  accessibilityRole="button"
  accessibilityState={{ disabled: !isValid }}
  style={[styles.primary, !isValid && styles.primaryDisabled]}
>
  <Text style={styles.primaryText}>Simpan</Text>
</Pressable>
```

Saat `isValid` bernilai `false`, prop `disabled` membuat tombol tidak bisa diketuk, dan gaya `primaryDisabled` membuatnya tampak pudar. Diagram berikut merangkum apa yang terjadi setiap kali kamu mengetik satu huruf:

<Flow nodes={["Ketik di TextInput", "setField", "Render ulang", "validateTask(form)", "Pesan error & tombol"]} labels={["onChangeText", "state form berubah", "hitung errors", "touched + isValid"]} caption="Satu ketikan memicu validasi ulang" />

<Callout type="tip" title="Tombol nonaktif perlu penjelasan">

Tombol abu-abu tanpa keterangan membingungkan, karena pengguna tidak tahu apa yang kurang. Itu sebabnya pesan error tetap muncul di bawah kolom setelah kolom ditinggalkan. Ada juga pola lain yang umum: tombol selalu aktif, lalu saat ditekan semua error ditampilkan sekaligus. Kamu akan mencobanya di Latihan 2.

</Callout>

## Fokus berantai dengan returnKeyType dan useRef

<Callout type="analogi" title="Seperti petugas loket yang menunjuk kolom berikutnya">

Di loket pendaftaran, setiap kali kamu selesai menulis satu kolom, petugas menunjuk kolom berikutnya: "Sekarang nomor HP, Kak." Kamu tidak perlu mencari-cari kolom sendiri.

Petugas yang menunjuk = `onSubmitEditing`. Supaya bisa menunjuk, petugas harus tahu letak kolom berikutnya. Catatan letak itu = `ref`. Gerakan menunjuk = `focus()`. Tulisan "Next" di tombol Enter hanya papan petunjuk. Ia tidak memindahkan apa pun sendiri.

</Callout>

Di form yang enak dipakai, pengguna mengisi kolom satu per satu tanpa mengangkat jari dari keyboard. Tombol Enter di kolom judul berlabel "Next", dan menekannya memindahkan kursor ke kolom berikutnya. Kolom yang sedang menerima ketikan disebut kolom yang punya **fokus**. Untuk memindahkan fokus, dibutuhkan tiga hal:

1. `returnKeyType="next"` mengganti label tombol Enter menjadi "Next".
2. `useRef(null)` membuat **ref**, yaitu wadah untuk menyimpan "pegangan" ke `TextInput` berikutnya. Wadah itu diisi lewat prop `ref` di kolom tujuan.
3. `onSubmitEditing` memanggil `ref.current?.focus()` saat Enter ditekan. Tanda `?.` berarti "panggil hanya kalau pegangannya sudah ada".

```jsx
const courseRef = useRef(null);
const deadlineRef = useRef(null);
const descriptionRef = useRef(null);

<TextInput
  value={form.title}
  onChangeText={(text) => setField('title', text)}
  returnKeyType="next"
  submitBehavior="submit"
  onSubmitEditing={() => courseRef.current?.focus()}
/>
<TextInput
  ref={courseRef}
  value={form.course}
  onChangeText={(text) => setField('course', text)}
  returnKeyType="next"
  submitBehavior="submit"
  onSubmitEditing={() => deadlineRef.current?.focus()}
/>
```

Hasilnya, Enter di kolom judul memindahkan kursor ke kolom mata kuliah, lalu dari sana ke kolom deadline.

`submitBehavior="submit"` membuat Enter hanya mengirim sinyal "selesai", tanpa melepas fokus. Tanpa prop ini, kolom satu baris memakai perilaku `blurAndSubmit`: fokus dilepas dulu, sehingga keyboard sempat turun lalu naik lagi. Prop ini menggantikan `blurOnSubmit` yang sudah usang.

Kolom deskripsi sengaja diletakkan sebagai kolom teks terakhir. Di kolom `multiline` (banyak baris), Enter dipakai untuk membuat baris baru, jadi rantai fokus berhenti di situ. Kalau kamu memaksanya dengan `submitBehavior="submit"`, pengguna tidak bisa lagi membuat baris baru.

## Contoh kecil: login dengan secureTextEntry

Form login berguna untuk mencoba prop yang belum terpakai di form tugas, terutama `secureTextEntry`. Prop ini mengganti huruf password dengan titik, seperti layar ATM yang hanya menampilkan bintang saat kamu mengetik PIN. Buat file latihan `src/app/login.js`. Layar login sungguhan, lengkap dengan token (tanda sudah masuk dari server), dibangun di Track 3.

```jsx title="src/app/login.js"
import { router } from 'expo-router';
import { useRef, useState } from 'react';
import { Pressable, StyleSheet, Text, TextInput, View } from 'react-native';

export default function LoginScreen() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [showPassword, setShowPassword] = useState(false);
  const passwordRef = useRef(null);

  function masuk() {
    console.log('Login dengan', email);
    router.back();
  }

  return (
    <View style={styles.container}>
      <TextInput
        value={email}
        onChangeText={setEmail}
        placeholder="demo@kampus.ac.id"
        keyboardType="email-address"
        autoCapitalize="none"
        autoCorrect={false}
        autoComplete="email"
        textContentType="emailAddress"
        returnKeyType="next"
        submitBehavior="submit"
        onSubmitEditing={() => passwordRef.current?.focus()}
        accessibilityLabel="Email"
        style={styles.input}
      />
      <View style={styles.row}>
        <TextInput
          ref={passwordRef}
          value={password}
          onChangeText={setPassword}
          placeholder="Password"
          secureTextEntry={!showPassword}
          autoCapitalize="none"
          autoComplete="current-password"
          textContentType="password"
          returnKeyType="go"
          onSubmitEditing={masuk}
          accessibilityLabel="Password"
          style={[styles.input, styles.flex]}
        />
        <Pressable
          onPress={() => setShowPassword((v) => !v)}
          accessibilityRole="button"
          accessibilityLabel={showPassword ? 'Sembunyikan password' : 'Tampilkan password'}
          hitSlop={8}
          style={styles.toggle}
        >
          <Text>{showPassword ? 'Sembunyikan' : 'Lihat'}</Text>
        </Pressable>
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, padding: 16, gap: 12 },
  row: { flexDirection: 'row', gap: 8, alignItems: 'center' },
  flex: { flex: 1 },
  input: { borderWidth: 1, borderColor: '#cbd5e1', borderRadius: 10, padding: 12, backgroundColor: 'white' },
  toggle: { padding: 12 },
});
```

Hal-hal yang perlu kamu perhatikan di kode ini:

- `keyboardType="email-address"` memunculkan keyboard yang punya tombol `@`.
- `autoCapitalize="none"` penting untuk email. Tanpa ini, huruf pertama email menjadi kapital, dan login bisa gagal di server yang membedakan huruf besar dan kecil.
- `autoComplete` berlaku di Android dan iOS, sedangkan `textContentType` khusus iOS. Keduanya membantu password manager (aplikasi penyimpan password) mengisi akun otomatis.
- `secureTextEntry={!showPassword}` menyembunyikan password, kecuali saat tombol "Lihat" sedang aktif.
- Kolom password memakai `returnKeyType="go"`, dan `onSubmitEditing` langsung memanggil `masuk`. Jadi Enter di kolom ini sama dengan menekan tombol masuk.
- `hitSlop={8}` memperluas area ketuk tombol "Lihat" sebesar 8 poin ke segala arah.

Untuk membuka layar ini, tambahkan `<Link href="/login">` di `profile.js` atau ketik URL `/login` di web.

## Keyboard tidak boleh menutupi input

<Callout type="analogi" title="Seperti nampan yang ditaruh di atas buku catatan">

Kamu sedang menulis di buku catatan di meja kantin. Tiba-tiba teman menaruh nampan di separuh bawah buku. Supaya tetap bisa menulis, kamu geser bukunya ke atas, atau kamu balik halamannya sampai baris yang ingin ditulis terlihat.

Nampan = keyboard. Menggeser buku ke atas = `KeyboardAvoidingView` yang menambah ruang di bawah. Membalik ke baris yang terlihat = `ScrollView` yang bisa digulir. Bedanya, keyboard memberi tahu tingginya ke aplikasi, jadi geserannya bisa dihitung pas dan terjadi otomatis.

</Callout>

Ada tiga alat bawaan React Native yang dipakai bersama:

- **`KeyboardAvoidingView`** memberi ruang saat keyboard naik. Di iOS, pakai `behavior="padding"`: komponen menambah ruang kosong di bawah setinggi keyboard. Di Android, panduan Expo menyarankan `undefined`, karena Android sudah menggeser jendela sendiri.
- **`ScrollView`** dengan `keyboardShouldPersistTaps="handled"` membuat ketukan pada tombol tetap diproses saat keyboard terbuka. Nilai bawaannya `"never"`, sehingga ketukan pertama hanya menutup keyboard.
- **`Keyboard.dismiss()`** menutup keyboard lewat kode, misalnya tepat sebelum modal ditutup.

```jsx
<KeyboardAvoidingView
  style={{ flex: 1 }}
  behavior={Platform.OS === 'ios' ? 'padding' : undefined}
>
  <ScrollView
    contentContainerStyle={styles.container}
    keyboardShouldPersistTaps="handled"
    keyboardDismissMode="on-drag"
  >
    {/* semua kolom dan tombol */}
  </ScrollView>
</KeyboardAvoidingView>
```

`Platform.OS === 'ios' ? 'padding' : undefined` artinya: kalau berjalan di iOS pakai `padding`, selain itu jangan pakai apa-apa.

`style={{ flex: 1 }}` wajib ada. Tanpa itu, `KeyboardAvoidingView` hanya setinggi isinya, sehingga ruang tambahan tidak mendorong apa pun. `keyboardDismissMode="on-drag"` menutup keyboard saat pengguna menggulir layar. Kalau bagian bawah masih sedikit tertutup di iOS, misalnya karena ada header Stack di atas, naikkan `keyboardVerticalOffset` sebesar tinggi header itu.

Untuk form yang lebih panjang, ada library khusus: [`react-native-keyboard-controller`](https://kirillzyusko.github.io/react-native-keyboard-controller). Komponen `KeyboardAwareScrollView` di dalamnya otomatis menggulir ke kolom yang sedang fokus. `KeyboardToolbar` menampilkan tombol sebelumnya, berikutnya, dan selesai di atas keyboard, termasuk untuk kolom `multiline`.

Kedua tab memakai dua fungsi bantu berikut:

```js
function toDateText(date) {
  const y = date.getFullYear();
  const m = String(date.getMonth() + 1).padStart(2, '0');
  const d = String(date.getDate()).padStart(2, '0');
  return y + '-' + m + '-' + d;
}

function parseDateText(text) {
  const [y, m, d] = text.split('-').map(Number);
  return new Date(y, m - 1, d);
}

const deadlineDate =
  form.deadline && !errors.deadline ? parseDateText(form.deadline) : new Date();
```

- `toDateText` mengubah objek `Date` menjadi teks seperti `2026-07-15`. `padStart(2, '0')` menambah nol di depan, jadi bulan 7 ditulis `07`.
- `parseDateText` melakukan kebalikannya, dari teks menjadi `Date`.
- `deadlineDate` adalah tanggal yang ditunjukkan picker saat dibuka: deadline yang sudah diisi, atau hari ini kalau kolomnya kosong atau salah.

<Callout type="warning" title="Jangan pakai toISOString untuk tanggal lokal">

`date.toISOString().slice(0, 10)` mengubah waktu ke UTC dulu. **UTC** adalah jam patokan dunia, tujuh jam di belakang WIB. Tanggal 15 Juli pukul 00.30 WIB sama dengan 14 Juli pukul 17.30 UTC, sehingga deadline mundur sehari. Gunakan `getFullYear`, `getMonth`, dan `getDate` seperti `toDateText` di atas.

</Callout>

## Aksesibilitas form

<Callout type="analogi" title="Seperti membacakan formulir untuk teman">

Bayangkan temanmu tidak bisa melihat, dan kamu membacakan formulir untuknya. Ada kolom yang hanya berisi tulisan pensil tipis "misal: Basis Data", dan tulisan itu terhapus begitu kolomnya diisi. Kamu jadi bingung harus menyebut kolom itu apa.

Kamu yang membacakan = pembaca layar. Nama kolom yang tercetak jelas = `accessibilityLabel`. Tulisan pensil tipis = placeholder. Bedanya, pembaca layar tidak bisa menebak dari tampilan. Ia hanya membacakan apa yang kamu tulis di kode.

</Callout>

**Pembaca layar** (TalkBack di Android, VoiceOver di iOS) adalah fitur HP yang membacakan isi layar dengan suara. Beberapa kebiasaan kecil yang membantu penggunanya:

- Beri `accessibilityLabel` pada setiap `TextInput`. Placeholder bukan label, karena placeholder hilang begitu pengguna mengetik.
- Tambahkan `accessibilityHint` untuk aturan yang tidak terlihat, misalnya "Format tahun-bulan-tanggal".
- Tombol pilihan memakai `accessibilityRole="radio"` dengan `accessibilityState` berisi `checked`. Tombol Simpan memakai `accessibilityState` berisi `disabled`.
- Pesan error memakai `accessibilityLiveRegion="polite"`, supaya langsung dibacakan di Android saat muncul. Di iOS, panggil `AccessibilityInfo.announceForAccessibility(pesan)` kalau perlu.
- Area ketuk minimal sekitar 44 poin, kira-kira selebar ujung jari. Untuk tombol kecil seperti "Lihat", perluas dengan `hitSlop`.

- `EMPTY` adalah isi form saat modal baru dibuka.
- `errorFor(name)` menggabungkan `touched` dan `errors`: pesan hanya muncul untuk kolom yang sudah ditinggalkan.
- `simpan` berhenti kalau form belum valid. Kalau valid, keyboard ditutup, data dicetak ke terminal, lalu `router.back()` menutup modal.

- `styles.inputError` memberi garis merah pada kolom yang salah.

`FieldError` ditulis di luar `NewTaskScreen`. Kalau ditulis di dalamnya, setiap render membuat komponen baru, dan React menganggapnya komponen yang berbeda. Untuk form yang lebih besar, [react-hook-form](https://react-hook-form.com) bisa mengurus state, `touched`, dan error untukmu. Setiap input dibungkus `Controller`, dan aturannya bisa ditulis dengan [Zod](/glosarium#zod) (library validasi). Pahami dulu versi manual ini, supaya kamu tahu apa yang dikerjakan library tersebut di balik layar.

## Kesalahan umum

| Gejala / pesan | Penyebab | Perbaikan |
| --- | --- | --- |
| `TypeError: Cannot read property 'value' of undefined` | Menulis `onChangeText={(e) => setField('title', e.target.value)}` seperti di web | Argumen `onChangeText` sudah berupa string: `(text) => setField('title', text)` |
| Ketikan tidak muncul, kolom selalu kosong | `value` dipasang tetapi state tidak pernah diubah, atau `setField` menimpa seluruh objek tanpa `...prev` | Pastikan `onChangeText` memanggil setter, dan pakai spread `...prev` |
| `TypeError: Cannot read property 'focus' of null` | `ref` tidak terpasang ke `TextInput`, misalnya dipasang ke komponen buatan sendiri yang tidak meneruskan `ref` | Pasang `ref={courseRef}` langsung di `TextInput`, dan pakai `courseRef.current?.focus()` |
| `Error: Text strings must be rendered within a <Text> component.` | Menulis `{form.title.length && <Text>…</Text>}`. Saat judul kosong, hasilnya angka `0`, dan angka itu dirender di luar `Text` | Pakai ternary `kondisi ? <Text>…</Text> : null`, artinya kalau kondisi benar tampilkan `Text`, kalau salah tampilkan kosong. Bisa juga pakai kondisi boolean seperti `length > 0` |

<Solution>

const titleRef = useRef(null);
const [submitted, setSubmitted] = useState(false);

function errorFor(name) {

}

  const firstError = ['title', 'course', 'deadline', 'description'].find((name) => errors[name]);

## Ringkasan

- Form terkontrol memakai `value` dan `onChangeText`. `onChangeText` langsung memberi string. Simpan semua kolom dalam satu objek `form` dan ubah lewat `setField(name, value)`.
- Validasi adalah fungsi murni yang mengembalikan objek error. Error muncul setelah kolom disentuh. Tombol Simpan mati selama form belum valid.
- `keyboardType`, `autoCapitalize`, `autoCorrect`, `autoComplete`, dan `secureTextEntry` memilih keyboard yang cocok untuk tiap kolom.
- Untuk pindah kolom dengan Enter, pakai `returnKeyType="next"`, `submitBehavior="submit"`, dan `onSubmitEditing` yang memanggil `ref.current?.focus()`.
- Agar kolom tidak tertutup keyboard, pakai `KeyboardAvoidingView` (iOS `padding`, Android `undefined`, `flex: 1`) dan `ScrollView` dengan `keyboardShouldPersistTaps="handled"`. Untuk form panjang, pakai `react-native-keyboard-controller`.
- Prioritas memakai deretan `Pressable`, status memakai `Switch`. Setiap kontrol diberi label dan peran untuk pembaca layar.
