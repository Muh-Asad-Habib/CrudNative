## Pengantar

Buka proyek `latihan-rn` yang kamu buat di [Expo Router](/belajar/react-native/expo-router) dan [Form & Keyboard](/belajar/react-native/form-keyboard). Isi modal "Tugas Baru", tekan **Simpan**, lalu kembali ke daftar. Tugas barunya tidak muncul.

Kenapa? Layar daftar membaca array `TASKS` dari `src/lib/data.js`. Form hanya menyimpan isian di state miliknya sendiri. Keduanya tidak pernah bertukar data.

Ada masalah kedua. Tutup aplikasinya, lalu buka lagi. Semua perubahan hilang. State React hanya hidup di memori kerja HP (RAM), dan memori itu dikosongkan begitu aplikasi ditutup.

Dua masalah ini butuh dua solusi yang berbeda:

1. **State global**, yaitu satu tempat data yang bisa dibaca dan diubah oleh banyak layar. Kita memakai **Context + `useReducer`** bawaan React. Setelah itu kita bandingkan dengan **Zustand**, sebuah pustaka (library, kode siap pakai buatan orang lain yang dipasang lewat npm).
2. **Penyimpanan lokal**, yaitu menulis data ke penyimpanan HP agar tetap ada setelah aplikasi ditutup. Alatnya **AsyncStorage** untuk data biasa, **SecureStore** untuk rahasia seperti token login, dan **expo-sqlite** untuk data yang besar.

Di akhir pelajaran, layar daftar, detail, dan modal di `latihan-rn` memakai satu sumber data tugas yang sama. Isinya juga tetap ada setelah aplikasi dibuka ulang.

## Prop drilling: gejala state yang salah tempat

<Callout type="analogi" title="Seperti titip paket berantai di kos-kosan">

Kamarmu di lantai 3 kos. Kurir tidak boleh naik, jadi paketmu dititipkan ke satpam. Satpam menitipkan ke ibu kos, ibu kos ke penghuni lantai 2, lalu penghuni lantai 2 mengantar ke kamarmu. Tiga orang itu tidak butuh paketnya. Mereka hanya mengoper. Kalau satu orang lupa, paketnya tidak sampai.

Di kode: paket = data `tasks`, kurir = komponen paling atas yang menyimpan state, para perantara = komponen di tengah, dan kamu = `TaskItem` yang benar-benar memakai datanya.

</Callout>

Di [State & Event](/belajar/react-native/state-event) kamu sudah belajar **lifting state up**: kalau dua komponen butuh data yang sama, simpan state di induk terdekat, lalu turunkan lewat props. Cara itu tepat selama induknya dekat.

Di aplikasi dengan banyak layar, induk bersama dari daftar, detail, dan modal adalah layout root `src/app/_layout.js`, yaitu file paling luar yang membungkus semua layar. Masalahnya, kamu tidak merender layar-layar itu sendiri. Expo Router yang merendernya berdasarkan URL. Jadi kamu tidak bisa menulis `<TaskListScreen tasks={tasks} />`. Seandainya bisa pun, data harus melewati banyak lapisan yang tidak membutuhkannya:

<Flow nodes={["RootLayout (state tasks)", "TabLayout", "TaskListScreen", "FlatList", "TaskItem"]} labels={["props", "props", "props", "props"]} caption="Prop drilling: tasks dan onToggle dioper empat kali hanya agar sampai ke TaskItem" />

Pola ini disebut **prop drilling**: props "dibor" menembus komponen perantara yang hanya mengoper tanpa memakainya. Gejalanya mudah dikenali:

- Ada komponen yang menerima props, tetapi tidak pernah membacanya.
- Mengganti nama satu props memaksamu mengedit lima file.
- Menambah layar baru berarti menyambung "kabel" props baru dari atas.

Lalu kenapa tidak memakai variabel biasa, misalnya `TASKS.push(tugasBaru)`? Karena React tidak tahu variabel itu berubah. React hanya menggambar ulang layar (**render ulang**) saat state atau props berubah. Variabel biasa tidak memicu render ulang, jadi layar tetap menampilkan data lama. Kita butuh state yang tinggal **di atas semua layar**, tetapi tetap **memicu render ulang** saat berubah. [Context](/glosarium#context) menyediakan state seperti itu.

## useReducer: semua perubahan di satu tempat

<Callout type="analogi" title="Seperti menyetor uang lewat teller bank">

Di bank, kamu tidak boleh membuka brankas dan mengubah saldo sendiri. Kamu mengisi slip, misalnya "setor Rp100.000 ke rekening Andi", lalu menyerahkannya ke teller. Teller memproses slip itu dengan aturan yang sama untuk semua nasabah, lalu mencatat saldo baru.

- slip = **action** (objek yang menjelaskan apa yang terjadi)
- menyerahkan slip ke teller = **`dispatch`**
- teller beserta aturannya = **reducer**
- saldo baru = **state** berikutnya

Ada satu perbedaan. Teller menulis di buku yang sama. Reducer selalu membuat "buku" baru dan membiarkan buku lama utuh.

</Callout>

Sebelum masuk ke Context, kita rapikan dulu cara mengubah data. Ada empat operasi: tambah, centang, ubah, dan hapus. Daripada menulis `setTasks` di empat layar berbeda, kumpulkan semua aturannya di satu fungsi bernama **reducer**.

Reducer menerima dua hal: state sekarang dan sebuah **action**. Action adalah objek biasa yang menjelaskan apa yang terjadi, misalnya `{ type: 'toggle', id: '1' }`. Reducer lalu mengembalikan state baru.

Reducer harus berupa **fungsi murni**: hasilnya hanya bergantung pada input, tanpa pekerjaan sampingan seperti memanggil API. Reducer juga tidak boleh mengubah array lama. Ia selalu membuat salinan baru, sesuai prinsip [immutability](/glosarium#immutability) (data lama tidak disentuh, perubahan ditulis di salinan).

```js title="tasks-reducer-demo.mjs"
function tasksReducer(tasks, action) {
  switch (action.type) {
    case 'add':
      return [...tasks, action.task];
    case 'toggle':
      return tasks.map((task) => (task.id === action.id ? { ...task, done: !task.done } : task));
    case 'update':
      return tasks.map((task) => (task.id === action.id ? { ...task, ...action.changes } : task));
    case 'remove':
      return tasks.filter((task) => task.id !== action.id);
    default:
      throw new Error(`Action tidak dikenal: ${action.type}`);
  }
}

let tasks = [{ id: '1', title: 'ERD sistem perpustakaan', course: 'Basis Data', done: false }];
tasks = tasksReducer(tasks, { type: 'add', task: { id: '2', title: 'Latihan query JOIN', course: 'Basis Data', done: false } });
tasks = tasksReducer(tasks, { type: 'toggle', id: '1' });
tasks = tasksReducer(tasks, { type: 'update', id: '2', changes: { title: 'Latihan LEFT JOIN' } });
console.log(tasks.map((t) => `${t.id}:${t.title}:${t.done}`));
tasks = tasksReducer(tasks, { type: 'remove', id: '1' });
console.log(tasks.length);
```

```txt
[ '1:ERD sistem perpustakaan:true', '2:Latihan LEFT JOIN:false' ]
1
```

Cara membaca kode di atas:

- `switch (action.type)` memilih aturan berdasarkan jenis action.
- `'add'` membuat array baru berisi semua tugas lama (`...tasks` artinya "salin semua isi `tasks`") ditambah tugas baru.
- `'toggle'` dan `'update'` memakai `map`. Tugas dengan `id` yang cocok diganti salinan yang sudah diubah. Tugas lain dibiarkan apa adanya.
- `'remove'` memakai `filter` untuk membuang tugas dengan `id` itu.
- Action yang tidak dikenal langsung menjadi error, supaya salah ketik seperti `'tooggle'` cepat ketahuan.

Reducer hanyalah fungsi JavaScript biasa. Jadi kamu bisa mengujinya dengan `node tasks-reducer-demo.mjs` tanpa HP, tanpa Expo, dan tanpa React. Di komponen, reducer dipasang dengan hook `useReducer`:

```js
const [tasks, dispatch] = useReducer(tasksReducer, TASKS);
dispatch({ type: 'toggle', id: '2' }); // React memanggil tasksReducer, lalu render ulang
```

`useReducer` menerima reducer dan data awal (`TASKS`). Hasilnya dua hal: `tasks` (state sekarang) dan `dispatch` (fungsi untuk mengirim action). Bedanya dengan `useState`, kamu tidak menulis nilai baru secara langsung. Kamu "melapor" lewat `dispatch(action)`, lalu reducer yang menentukan bentuk state berikutnya.

## Context + useReducer: store tugas bersama

<Callout type="analogi" title="Seperti pengumuman di grup WhatsApp kelas">

Ketua kelas tidak menelepon 40 mahasiswa satu per satu untuk mengabarkan jadwal kuis. Ia cukup mengirim pengumuman ke grup WA kelas. Semua anggota grup bisa langsung membacanya.

- grup WA = **Context**
- ketua kelas yang mengirim pengumuman = **provider**
- anggota yang membaca = komponen yang memanggil `useContext`
- hanya anggota grup yang bisa membaca = hanya komponen **di dalam** provider yang bisa memakai context

Ada satu sifat lain yang mirip. Setiap ada pesan baru, HP semua anggota ikut berbunyi, walaupun pesannya tidak penting bagi sebagian orang. Context juga begitu. Kita bahas di akhir bagian ini.

</Callout>

**Context** adalah saluran data bawaan React. Komponen di atas menaruh nilai ke saluran itu lewat **provider** (komponen pembungkus yang "menyiarkan" nilai). Komponen mana pun di bawahnya bisa membaca nilai itu dengan `useContext`, tanpa lewat props.

Gabungkan Context dengan reducer tadi, dan kamu punya **store** global kecil tanpa pustaka tambahan. Store adalah tempat menyimpan state bersama beserta fungsi-fungsi untuk mengubahnya.

Kode yang bukan layar disimpan di `src/features`, bukan di `src/app`. Alasannya, Expo Router menganggap setiap file di `src/app` sebagai route (halaman).

<FileTree title="latihan-rn" tree={`
src/
  app/
    * _layout.js # dibungkus TasksProvider
    (tabs)/
      index.js # membaca tasks
      profile.js
    tasks/
      [id].js # toggle + hapus
      new.js # addTask

    data.js # TASKS awal
`} />

```jsx title="src/features/tasks/tasks-context.js"
import { createContext, useContext, useMemo, useReducer } from 'react';
import { TASKS } from '../../lib/data';

const TasksContext = createContext(null);

export function tasksReducer(tasks, action) {
  switch (action.type) {
    case 'add':
      return [...tasks, action.task];
    case 'toggle':
      return tasks.map((task) => (task.id === action.id ? { ...task, done: !task.done } : task));
    case 'update':
      return tasks.map((task) => (task.id === action.id ? { ...task, ...action.changes } : task));
    case 'remove':
      return tasks.filter((task) => task.id !== action.id);
    default:
      throw new Error(`Action tidak dikenal: ${action.type}`);
  }
}

export function TasksProvider({ children }) {
  const [tasks, dispatch] = useReducer(tasksReducer, TASKS);

  const value = useMemo(
    () => ({
      tasks,
      addTask: (input) =>
        dispatch({ type: 'add', task: { ...input, id: String(Date.now()), done: false } }),
      toggleTask: (id) => dispatch({ type: 'toggle', id }),
      updateTask: (id, changes) => dispatch({ type: 'update', id, changes }),
      removeTask: (id) => dispatch({ type: 'remove', id }),
    }),
    [tasks],
  );

  return <TasksContext value={value}>{children}</TasksContext>;
}

export function useTasks() {
  const context = useContext(TasksContext);
  if (!context) {
    throw new Error('useTasks harus dipakai di dalam <TasksProvider>');
  }
  return context;
}
```

Isi file ini, bagian per bagian:

- `createContext(null)` membuat "grup WA"-nya. Nilai awalnya `null`, artinya belum ada provider yang mengisi.
- `TasksProvider` menyimpan state dengan `useReducer`, lalu membagikan `value` ke semua komponen di dalamnya (`children`).
- **Layar tidak memanggil `dispatch` langsung.** Mereka memakai fungsi bernama seperti `addTask` dan `toggleTask`. Bentuk action jadi urusan internal file ini, sehingga mudah diganti nanti.
- **`useTasks` adalah [custom hook](/glosarium#custom-hook)**, yaitu fungsi buatanmu sendiri yang memakai hook React. Ia membungkus `useContext`. Kalau ada yang lupa memasang provider, ia langsung mendapat pesan error yang jelas, bukan error samar.
- **`useMemo`** membuat objek `value` tetap objek yang sama selama `tasks` tidak berubah. Tanpa itu, setiap render provider membuat objek baru, dan semua pemakai context ikut render ulang tanpa perlu.
- **Id berupa string** (`String(Date.now())`), sama seperti data di `src/lib/data.js`. Param route dari URL juga selalu string, jadi perbandingan `item.id === id` tetap cocok.
- **`<TasksContext value={value}>`** adalah sintaks React 19. Kode lama menulis `<TasksContext.Provider value={value}>`, dan bentuk itu masih berjalan.

</Callout>

## Alternatif: Zustand dengan selector

[Zustand](/glosarium#zustand) adalah pustaka state global yang sangat kecil. Store dibuat dengan `create`, dan tidak perlu provider sama sekali. Kelebihan utamanya adalah **selector**: komponen memilih potongan state yang ia butuhkan, dan hanya render ulang kalau potongan itu berubah.

```bash
npx expo install zustand
```

```js title="src/features/tasks/tasks-store.js"
import { create } from 'zustand';
import { TASKS } from '../../lib/data';

export const useTasksStore = create((set) => ({
  tasks: TASKS,
  addTask: (input) =>
    set((state) => ({ tasks: [...state.tasks, { ...input, id: String(Date.now()), done: false }] })),
  toggleTask: (id) =>
    set((state) => ({
      tasks: state.tasks.map((task) => (task.id === id ? { ...task, done: !task.done } : task)),
    })),
  updateTask: (id, changes) =>
    set((state) => ({
      tasks: state.tasks.map((task) => (task.id === id ? { ...task, ...changes } : task)),
    })),
  removeTask: (id) => set((state) => ({ tasks: state.tasks.filter((task) => task.id !== id) })),
}));
```

`set` menggabungkan objek yang kamu kembalikan ke state lama, jadi fungsi `addTask` dan kawan-kawan tidak hilang. Perbandingan cara pakainya:

Selector harus mengembalikan nilai yang stabil. Angka, string, atau referensi yang sudah ada di state (`state.tasks`) aman. Kalau selector membuat array atau objek **baru** setiap dipanggil, bungkus dengan `useShallow`:

```jsx
import { useShallow } from 'zustand/react/shallow';

const { addTask, removeTask } = useTasksStore(
  useShallow((state) => ({ addTask: state.addTask, removeTask: state.removeTask })),
);
```

Pilih **satu** pendekatan untuk satu jenis data. Di sisa pelajaran ini `latihan-rn` tetap memakai Context, tetapi bagian penyimpanan juga menunjukkan versi Zustand-nya.

## Menyimpan data dengan AsyncStorage

State global menyelesaikan masalah pertama. Masalah kedua, data hilang saat aplikasi ditutup, butuh **penyimpanan lokal**. [AsyncStorage](/glosarium#async-storage) adalah penyimpanan *key-value* sederhana: kamu menyimpan teks di bawah sebuah nama kunci, lalu membacanya lagi nanti. Semua method-nya asinkron (mengembalikan Promise), datanya **tidak dienkripsi**, dan bertahan sampai aplikasi dihapus atau datanya dibersihkan. Paket ini sudah ada di Expo Go, jadi cukup dipasang:

```bash
npx expo install @react-native-async-storage/async-storage
```

API intinya hanya tiga:

| Method | Hasil |
| --- | --- |
| `AsyncStorage.setItem(key, string)` | Menyimpan teks di bawah `key` |
| `AsyncStorage.getItem(key)` | Teks yang tersimpan, atau `null` kalau belum ada |
| `AsyncStorage.removeItem(key)` | Menghapus satu kunci |

AsyncStorage **hanya menyimpan string**. Array tugas harus diubah ke [JSON](/glosarium#json) dengan `JSON.stringify` saat menyimpan, dan dikembalikan dengan `JSON.parse` saat membaca. Pola ini sama dengan `useLocalStorage` di [Effect, List & Custom Hook](/belajar/react-native/effect-list-custom-hook). Bedanya, `localStorage` di browser bersifat sinkron, sedangkan AsyncStorage harus ditunggu dengan `await`.

### Kunci berversi

Beri nama kunci yang jelas dan sertakan versi, misalnya `latihan-rn:tasks:v1`. Suatu hari bentuk data pasti berubah, misalnya tugas mendapat field `priority`. Data lama di HP pengguna masih berbentuk v1. Dengan kunci berversi, kode baru bisa membaca `v2`, dan kalau belum ada, membaca `v1` lalu mengubahnya. ## Zustand + persist

Kalau kamu memilih Zustand, persistensi tidak perlu ditulis manual. Middleware `persist` membungkus store, membaca data saat store dibuat, dan menyimpan setiap kali `set` dipanggil. `createJSONStorage(() => AsyncStorage)` menyambungkan AsyncStorage dan mengurus `JSON.stringify`/`JSON.parse` untukmu.

```js title="src/features/tasks/tasks-store.js" {1,3,7,22-28}
import AsyncStorage from '@react-native-async-storage/async-storage';
import { create } from 'zustand';
import { createJSONStorage, persist } from 'zustand/middleware';
import { TASKS } from '../../lib/data';

export const useTasksStore = create(
  persist(
    (set) => ({
      tasks: TASKS,
      addTask: (input) =>
        set((state) => ({ tasks: [...state.tasks, { ...input, id: String(Date.now()), done: false }] })),
      toggleTask: (id) =>
        set((state) => ({
          tasks: state.tasks.map((task) => (task.id === id ? { ...task, done: !task.done } : task)),
        })),
      updateTask: (id, changes) =>
        set((state) => ({
          tasks: state.tasks.map((task) => (task.id === id ? { ...task, ...changes } : task)),
        })),
      removeTask: (id) => set((state) => ({ tasks: state.tasks.filter((task) => task.id !== id) })),
    }),
    {
      name: 'latihan-rn:tasks',
      storage: createJSONStorage(() => AsyncStorage),
      version: 1,
      partialize: (state) => ({ tasks: state.tasks }),
    },
  ),
);
```

- `name` adalah kunci di AsyncStorage.
- `version` disimpan bersama datanya. Kalau versinya berbeda, Zustand memanggil opsi `migrate(persistedState, version)` agar kamu bisa mengubah bentuk data lama.
- `partialize` memilih bagian state yang disimpan. Fungsi seperti `addTask` tidak perlu dan tidak bisa diubah ke JSON.

Hydration juga terjadi di sini dan berlangsung asinkron. Untuk menampilkan loading, tanyakan statusnya ke API `persist`:

```js title="src/features/tasks/use-tasks-hydrated.js"
import { useEffect, useState } from 'react';

  const [hydrated, setHydrated] = useState(false);

  useEffect(() => {
    const unsubscribe = useTasksStore.persist.onFinishHydration(() => setHydrated(true));
    setHydrated(useTasksStore.persist.hasHydrated());
    return unsubscribe;
  }, []);

  return hydrated;
}
```

## SecureStore untuk rahasia

AsyncStorage menyimpan teks apa adanya di penyimpanan aplikasi. Di HP yang di-*root*, lewat backup, atau saat debugging, isinya bisa dibaca. Itu tidak masalah untuk daftar tugas, tetapi berbahaya untuk **token login**: siapa pun yang memegang token bisa berpura-pura menjadi kamu.

Untuk rahasia kecil, pakai [SecureStore](/glosarium#secure-store) (`expo-secure-store`). Nilainya dienkripsi oleh sistem operasi: **Keychain** di iOS dan **Keystore** di Android. Paket ini juga sudah ada di Expo Go.

```bash
npx expo install expo-secure-store
```

Bungkus aksesnya dalam satu file agar nama kunci tidak tersebar ke mana-mana:

```js title="src/lib/token-storage.js"
import * as SecureStore from 'expo-secure-store';

const TOKEN_KEY = 'auth.accessToken';

export function saveToken(token) {
  return SecureStore.setItemAsync(TOKEN_KEY, token);
}

export function getToken() {
  return SecureStore.getItemAsync(TOKEN_KEY); // → string, atau null kalau belum ada
}

export function clearToken() {
  return SecureStore.deleteItemAsync(TOKEN_KEY);
}
```

Coba dari tab Profil dengan komponen kecil ini, lalu tampilkan `<TokenDemo />` di `src/app/(tabs)/profile.js`:

```jsx title="src/components/token-demo.js"
import { useState } from 'react';
```

Tekan **Simpan**, tutup aplikasi, buka lagi, lalu tekan **Baca**. Tokennya masih ada. Aturan pakai SecureStore:

- **Hanya untuk nilai kecil.** Nilai di atas sekitar 2 KB bisa gagal disimpan di sebagian perangkat. Token cocok, daftar tugas tidak.
- **Nilai harus string.** Objek perlu `JSON.stringify` dulu, sama seperti AsyncStorage.
- **Kunci hanya boleh berisi huruf, angka, `.`, `-`, dan `_`.** Kunci seperti `auth:token` ditolak.
- **Tidak tersedia di web.** Uji di Expo Go Android atau iOS. Kalau targetmu juga web, siapkan cabang khusus web.
- **Data di iOS bisa bertahan setelah aplikasi dihapus**, karena Keychain dikelola sistem. Di Android, datanya ikut terhapus. Jadi selalu sediakan logout yang memanggil `clearToken()`.
- **Jangan menyimpan password.** Simpan token dari server saja. Password cukup dikirim sekali saat login.

## Data besar: expo-sqlite

AsyncStorage menyimpan seluruh array sebagai satu teks. Untuk 50 tugas itu cepat. Untuk 5.000 catatan kuliah yang ingin dicari, difilter per mata kuliah, dan diurutkan berdasarkan deadline, menulis ulang seluruh array di setiap perubahan menjadi berat. Saat itulah kamu butuh database sungguhan di HP: **expo-sqlite**. SQL-nya sama dengan yang kamu pelajari di [Dasar SQL](/belajar/crud-backend/dasar-sql).

## Memilih alat yang tepat

| Kebutuhan | Alat | Contoh |
| --- | --- | --- |
| State milik satu komponen | `useState` | Teks yang sedang diketik |
| Dibagi komponen yang berdekatan | Lifting state + props | Form dan list dalam satu layar |
| Dibagi banyak layar, jarang berubah | Context (+ `useReducer`) | User login, tema, daftar tugas latihan |
| Store besar yang sering berubah | Zustand + selector | Filter, draft, keranjang belanja |
| Bertahan setelah aplikasi ditutup, tidak rahasia | AsyncStorage / `persist` | Preferensi, daftar tugas lokal |
| Rahasia kecil | SecureStore | Access token, refresh token |
| Data lokal banyak dan perlu query | expo-sqlite | Ribuan catatan offline |
| Data milik server | TanStack Query (Track 3) | Daftar tugas dari API |

Baris terakhir penting. Di Track 3, daftar tugas tidak lagi milik HP, melainkan milik database API. Data seperti itu disebut [server state](/glosarium#server-state): bisa basi kapan saja dan butuh loading, error, cache, serta refetch. Menyalinnya ke Context atau AsyncStorage secara manual membuat dua sumber kebenaran yang mudah tidak sinkron. Untuk itu kamu akan memakai [TanStack Query](/belajar/fullstack/tanstack-query). Context tetap terpakai untuk hal yang benar-benar milik aplikasi, misalnya status login.

## Kesalahan umum

<Callout type="warning" title="Lima jebakan yang paling sering muncul">

**1. Lupa memasang provider.** Layar yang memanggil `useTasks()` di luar `TasksProvider` menampilkan `Error: useTasks harus dipakai di dalam <TasksProvider>`. Tanpa pengecekan di hook, yang muncul hanya `TypeError` samar tentang membaca `tasks` dari `null`. Pastikan provider membungkus `Stack` di `src/app/_layout.js`.

**2. Data tersimpan tertimpa saat aplikasi dibuka.** Gejalanya, tugas yang kamu tambahkan selalu kembali ke data awal setelah restart. Penyebabnya, effect penyimpan berjalan sebelum hydration selesai. Jaga dengan `if (!hydrated) return;`.

**3. Menyimpan objek tanpa JSON.** AsyncStorage dan SecureStore hanya menerima string. Selalu `JSON.stringify` saat menulis dan `JSON.parse` di dalam `try/catch` saat membaca.

**4. Selector Zustand membuat objek baru.** `useTasksStore((s) => s.tasks.filter((t) => !t.done))` menghasilkan array baru setiap dipanggil. React mengira state terus berubah dan berhenti dengan `Maximum update depth exceeded`. Pilih `s.tasks` lalu filter di komponen, atau bungkus selector dengan `useShallow`.

**5. Kunci SecureStore tidak valid.** `saveToken` dengan kunci `auth:token` melempar `Invalid key provided to SecureStore. Keys must not be empty and contain only alphanumeric characters, ".", "-", and "_".` Ganti titik dua dengan titik, misalnya `auth.token`.

</Callout>

Satu lagi yang bukan error tetapi lubang keamanan: menyimpan token di AsyncStorage. Aplikasinya berjalan normal, tetapi tokennya tersimpan sebagai teks biasa. Token selalu masuk SecureStore.

<Exercise title="Migrasi data v1 ke v2" difficulty="sedang" hints={["Data v2 menambah field `priority` dengan nilai bawaan `'sedang'`.", "Saat memuat, baca kunci v2 dulu. Kalau `null`, baca kunci v1.", "Setelah migrasi berhasil, hapus kunci lama dengan `removeItem`."]}>

Tugas di `latihan-rn` sekarang butuh field `priority` (`'rendah' | 'sedang' | 'tinggi'`). Ubah kunci penyimpanan menjadi `latihan-rn:tasks:v2`. Pengguna yang masih punya data v1 tidak boleh kehilangan tugasnya: setiap tugas lama mendapat `priority: 'sedang'`.

<Solution>

```js title="src/features/tasks/tasks-context.js"
const STORAGE_KEY = 'latihan-rn:tasks:v2';
const LEGACY_KEY_V1 = 'latihan-rn:tasks:v1';

async function loadStoredTasks() {
  const json = await AsyncStorage.getItem(STORAGE_KEY);
  if (json !== null) return JSON.parse(json);

  const legacy = await AsyncStorage.getItem(LEGACY_KEY_V1);
  if (legacy === null) return null;

  const migrated = JSON.parse(legacy).map((task) => ({ priority: 'sedang', ...task }));
  await AsyncStorage.setItem(STORAGE_KEY, JSON.stringify(migrated));
  await AsyncStorage.removeItem(LEGACY_KEY_V1);
  return migrated;
}
```

Di dalam `load()`, ganti `AsyncStorage.getItem` dengan pemanggilan `loadStoredTasks()`, lalu `dispatch` hasilnya kalau tidak `null` (hasilnya sudah berupa array, jadi tidak perlu `JSON.parse` lagi). Urutan `{ priority: 'sedang', ...task }` membuat tugas yang kebetulan sudah punya `priority` tidak tertimpa. Jangan lupa menambahkan `priority` ke `TASKS` di `src/lib/data.js` dan ke `addTask`. Di Zustand, logika yang sama ditulis di opsi `migrate` dengan `version: 2`.

## Ringkasan

- **Prop drilling** muncul saat state disimpan jauh dari pemakainya. Di Expo Router, layar dirender oleh router, jadi data bersama butuh state global.
- **`useReducer`** memusatkan aturan perubahan (`add`, `toggle`, `update`, `remove`) dalam fungsi murni yang mudah diuji dengan `node`.
- **Context + `useReducer`** di `src/features/tasks/tasks-context.js` menghasilkan `TasksProvider` dan hook `useTasks`. Provider dipasang di `src/app/_layout.js`.
- **Zustand** tidak butuh provider, dan selector membuat komponen hanya render ulang saat potongan datanya berubah. Hindari selector yang membuat objek baru, atau pakai `useShallow`.
- **AsyncStorage** menyimpan string tanpa enkripsi. Pakai JSON, kunci berversi, dan status hydration: muat dulu, baru simpan. Di Zustand, gunakan `persist` dengan `createJSONStorage(() => AsyncStorage)`.
- **SecureStore** hanya untuk rahasia kecil seperti token. **expo-sqlite** untuk data lokal yang besar. Data milik server diurus TanStack Query di Track 3.
